<h1 style="text-align: center;">[RFC#0003] Plugin Contract and v1 Plugins</h1>

# Abstract

A plugin reads a workload's state and reports, per member, whether it is eligible, its role, its state and a reason. It never acts on the workload. This RFC fixes the contract every plugin follows and the two v1 plugins: `cnpg` for CloudNativePG and `declared` for a member named in the spec.

# Overview

| Plugin | Observes | Declaration | Member endpoint |
|---|---|---|---|
| `cnpg` | A CloudNativePG `Cluster`, and its `Pooler` when named | The `Cluster`'s `.spec.replica.primary` | The `Cluster`'s Service for the role, or the `Pooler`'s Service |
| `declared` | The member's Service | `spec.plugin.declared.active` | The member's Service |

A plugin runs at the site of the members it observes. A site never runs a plugin against another site's members; it reads their observations from the exchange ([RFC#0004]).

# Motivation

| Reason | Choice |
|---|---|
| Two actors that move a primary fight, and a router that acts on a database is a second actor. | A plugin only reads. |
| A plugin that holds write credentials can be turned into an actor by a bug. | A plugin gets read-only permissions and a reader with no write methods. |
| CloudNativePG labels the designated primary of a replica cluster `primary`, and that instance is read-only. Its `-rw` Service points at it too. | The `cnpg` plugin reads the `Cluster`'s spec and status, never only the pod label or the Service. |
| A `Cluster` promoted without a token and its peer both report a healthy state, `Ready`, and a primary out of recovery. Phase and conditions never show the split. | Writability comes from the reported recovery state, and the decision compares members across sites ([RFC#0002]). |
| Right after a promotion, the new primary reports `Applying configuration` and is out of recovery, then restarts. In the end-to-end test, a route to it in that window lasted up to one poll at the remote site, and every write in it failed. | `Applying configuration` is `Transitioning`. |
| A replica cluster's `-ro` Service is empty with one instance. | The `replica` role uses `-r` on a replica cluster, where every instance is read-only. |
| Linking against CloudNativePG's Go module ties Strait to one CloudNativePG version. | The `cnpg` plugin reads `Cluster` and `Pooler` as unstructured objects, and only the fields this RFC names. |
| Some workloads have no plugin that can observe their primary. | The `declared` plugin takes the primary from the spec. |

# Requirements

## Contract

1. A plugin MUST report, for every local member of a `SiteService`: role (`primary`, `replica` or `unknown`), eligible (true or false), state (`Stable`, `Transitioning` or `Unknown`), a reason, the observation time, and the member's endpoint Service with its ready addresses and target port.
2. A plugin MUST report the local site's declaration: the member it names as primary, or none.
3. A plugin MUST report `Unknown` when it cannot read the member. It MUST NOT report a guess.
4. A plugin MUST NOT create, update, patch or delete any object, and MUST NOT connect to the workload with write credentials. In code, it receives a `client.Reader`. Checked by review of `internal/plugin/`.
5. The RBAC rules for a plugin's resources MUST be `get`, `list` and `watch` only. Checked by review of the deploy manifests.
6. A member MUST NOT be eligible when its endpoint Service has no ready address.

## `cnpg`

7. Members MUST name a `Cluster` in the `SiteService`'s namespace, and MAY name a `Pooler` of that `Cluster`.
8. `spec.plugin.cnpg.role` MUST be `primary` with `Single` mode, and `replica` or `any` with `Set` mode.
9. A member MUST be writable (role `primary`, eligible, `Stable`) only when the `Cluster` is not a replica cluster and no state in the Transitioning table below holds.
10. The plugin MUST read only the fields named in the Design section.

## `declared`

11. In `Single` mode, `spec.plugin.declared.active` MUST name a member. That member has role `primary`, every other member role `replica`.
12. A member MUST be eligible when its Service has a ready address. Its state is `Stable` unless the Service cannot be read.

# Design

## Contract in code

```go
type Plugin interface {
	Observe(ctx context.Context, r client.Reader, svc *straitv1.SiteService, site string, now time.Time) observe.Report
}
```

The controller calls `Observe` on every reconcile of a `SiteService`, and on changes to the watched resources.

## `cnpg`: fields read

| Field | Use |
|---|---|
| `.spec.replica.self` | The cluster's own name in the distributed topology. Defaults to `.metadata.name`. |
| `.spec.replica.primary` | The declaration. |
| `.spec.replica.enabled` | Legacy replica clusters. When set, the cluster is a replica if true, and declares nothing. |
| `.spec.replica.promotionToken` | A promotion in progress, when it differs from `.status.lastPromotionToken`. |
| `.status.phase` | Transitioning phases. |
| `.status.currentPrimary`, `.status.targetPrimary` | A switchover inside the cluster, when they differ. |
| `.status.switchReplicaClusterStatus.inProgress` | A demotion in progress. |
| `.status.instancesReportedState[<currentPrimary>].isPrimary` | Whether the current primary instance is out of recovery, as the operator last polled it. The only status field that tracks writability; it lags the database by 1 to 3 seconds. |
| `Pooler` `.spec.cluster.name`, `.spec.type`, `.spec.pgbouncer.paused` | The Pooler belongs to the cluster, its type matches the role, and it is not paused. |

The declaration names a `Cluster` by its `self` name. The plugin maps it to the member whose `cnpg.cluster` has that name.

## `cnpg`: role and state

| Observed | Role | State |
|---|---|---|
| The `Cluster` cannot be read. | `unknown` | `Unknown` |
| The `Cluster` does not exist. | `unknown` | `Stable`, not eligible |
| The `Cluster` is a replica cluster. | `replica` | per the table below |
| Otherwise. | `primary` | per the table below |

| Transitioning when | Reason |
|---|---|
| `.status.phase` is `Switchover in progress`, `Failing over`, `Promoting to primary cluster`, `Setting up primary`, `Primary instance is being restarted in-place`, `Primary instance is being restarted without a switchover` or `Applying configuration`. | `Phase: <phase>` |
| `.status.currentPrimary` differs from `.status.targetPrimary`. | `PrimaryChanging` |
| `.status.switchReplicaClusterStatus.inProgress` is true. | `Demoting` |
| `.spec.replica.promotionToken` is set and differs from `.status.lastPromotionToken`. | `Promoting` |
| The spec names the cluster primary, and the current primary instance is not reported out of recovery. | `NotYetWritable` |
| The spec names another cluster primary, and the current primary instance is still reported out of recovery. | `NotYetReadOnly` |

## `cnpg`: endpoint by role

| Role | Endpoint Service | Eligible when |
|---|---|---|
| `primary` | `<cluster>-rw`, or the `Pooler`'s Service | writable, and the Service has a ready address |
| `replica` | `<cluster>-ro` on a primary cluster, `<cluster>-r` on a replica cluster | `Stable`, and the Service has a ready address |
| `any` | `<cluster>-r` | `Stable`, and the Service has a ready address |

# Security Considerations

- The controller's write permissions do not reach a plugin: a plugin receives a reader, and the RBAC rules for workload resources are read-only.
- The `cnpg` plugin never connects to PostgreSQL. It holds no database credential.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| Plugins are compiled into the controller. | A plugin that must run out of process, or that a third party writes. |
| No plugin reads Valkey Sentinel's view of the primary, and no plugin runs active checks (TCP, HTTP or SQL). | A user whose workload one of them would observe. |
| A routine configuration change also shows `Applying configuration`, so it routes nowhere for as long as CloudNativePG applies it. | A user whose configuration changes must not refuse connections. |
| A `cnpg` member and its `SiteService` share a namespace. | A user whose databases live in another namespace than the application. |
| A promotion restarts the new primary with a smart shutdown that waits up to `smartShutdownTimeout`, 180s by default, while sessions stay open. The `Cluster` reads `Transitioning` meanwhile, so Strait routes nowhere, even while a `Pooler` still takes writes. A short `smartShutdownTimeout` keeps the window short. | A user who needs writes during that window. |
