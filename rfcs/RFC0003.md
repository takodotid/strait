<h1 style="text-align: center;">[RFC#0003] Plugin Contract and v1 Plugins</h1>

# Abstract

A plugin reads a workload's state and reports, per member, whether it is eligible, its role, its state and a reason. It never acts on the workload. This RFC fixes the contract every plugin follows and the two v1 plugins: `cnpg` for CloudNativePG and `declared` for a member named in the spec.

# Overview

| Plugin | Observes | Declaration | Member endpoint |
|---|---|---|---|
| `cnpg` | A CloudNativePG `Cluster`, and its `Pooler` when named | The `Cluster`'s `.spec.replica.primary` | The `Cluster`'s Service for the role, or the `Pooler`'s Service |
| `declared` | The member's Service | `spec.plugin.declared.active` | The member's Service |

A plugin runs at the site of the members it observes. A site never runs a plugin against another site's members; it reads their observations from the exchange ([RFC#0004]).

# Motivation

| Reason | Choice |
|---|---|
| Two actors that move a primary fight, and a router that acts on a database is a second actor. | A plugin only reads. |
| A plugin that holds write credentials can be turned into an actor by a bug. | A plugin gets read-only permissions and a reader with no write methods. |
| CloudNativePG labels the designated primary of a replica cluster `primary`, and that instance is read-only. Its `-rw` Service points at it too. | The `cnpg` plugin reads the `Cluster`'s spec and status, never only the pod label or the Service. |
| A `Cluster` promoted without a token and its peer both report a healthy state, `Ready`, and a primary out of recovery. Phase and conditions never show the split. | Writability comes from the reported recovery state, and the decision compares members across sites ([RFC#0002]). |
| Right after a promotion, the new primary reports `Applying configuration` and is out of recovery, then restarts. In the end-to-end test, a route to it in that window lasted up to one poll at the remote site, and every write in it failed. | `Applying configuration` is `Transitioning`. |
| A replica cluster's `-ro` Service is empty with one instance. | The `replica` role uses `-r` on a replica cluster, where every instance is read-only. |
| Linking against CloudNativePG's Go module ties Strait to one CloudNativePG version. | The `cnpg` plugin reads `Cluster` and `Pooler` as unstructured objects, and only the fields this RFC names. |
| Some workloads have no plugin that can observe their primary. | The `declared` plugin takes the primary from the spec. |
| The chart grants the read of CloudNativePG's kinds only with `cnpg.enabled`, while the controller watched them whenever their CRDs existed. On envtest's API server, a manager that watched a kind it could not list stopped once its cache sync timed out. A cached read of such a kind waited for the caller's whole time limit, at each read: for a reconcile, 10s of the one worker that every `SiteService` shares. | The controller watches and reads CloudNativePG's kinds only while the chart grants the read. Otherwise the `cnpg` plugin reads nothing. |

# Requirements

## Contract

1. A plugin MUST report, for every local member of a `SiteService`: role (`primary`, `replica` or `unknown`), eligible (true or false), state (`Stable`, `Transitioning` or `Unknown`), a reason, the observation time, and the member's endpoint Service with its ready addresses and target port.
2. A plugin MUST report the local site's declaration: the member it names as primary, or none. When the site's workloads name more than one primary, the plugin MUST report each of them. The site then declares none to its peers ([RFC#0004]), and its own decision takes them as declarations that disagree ([RFC#0002], row 1). Checked by the unit test `TestLocalClustersDisagree`.
3. A plugin MUST report `Unknown` when it cannot read the member. It MUST NOT report a guess. Checked by the unit tests `TestCNPGReadFailed` and `TestDeclaredReadFailed`.
4. A plugin MUST NOT create, update, patch or delete any object, and MUST NOT connect to the workload with write credentials. In code, it receives a `client.Reader` that has no other method, whatever client the controller holds. Checked by review of `internal/plugin/` and by the unit tests `TestReadOnly` and `TestPluginReaderIsReadOnly`.
5. The RBAC rules for a plugin's resources MUST be `get`, `list` and `watch` only. Checked by the unit test `TestRBAC` on the rendered chart.
6. A member MUST NOT be eligible when its endpoint Service has no ready address.

## `cnpg`

7. Members MUST name a `Cluster` in the `SiteService`'s namespace, and MAY name a `Pooler` of that `Cluster`. Every `Cluster` of the topology MUST leave `.spec.replica.self` unset or set it to its `metadata.name`: the plugin maps a declaration to the member whose `cnpg.cluster` is the declared name, and never reads another site's `Cluster`. A declaration that names no member routes nowhere ([RFC#0002], rows 1 and 4), and sets the `SiteService`'s condition `DeclarationUnmatched` ([RFC#0002] requirement 42). Checked by inspecting each site's `Cluster`s, and by the unit test `TestCNPGSelf`. The checks of a `Pooler` in the Design section are checked by `TestCNPGPooler`.
8. `spec.plugin.cnpg.role` MUST be `primary` with `Single` mode, and `replica` or `any` with `Set` mode.
9. A member MUST be writable (role `primary`, eligible, `Stable`) only when the `Cluster` is not a replica cluster and no state in the Transitioning table below holds.
10. The plugin MUST read only the fields named in the Design section.

## `declared`

11. In `Single` mode, `spec.plugin.declared.active` MUST name a member. That member has role `primary`, every other member role `replica`.
12. A member MUST be eligible when its Service has a ready address. Its state is `Stable` unless the Service cannot be read.

## `cnpg` on and off

13. The controller MUST watch and read CloudNativePG's kinds only while its flag `--cnpg` is true. It MUST watch them only when their CRDs exist at its start. The chart MUST set the flag from `cnpg.enabled`, the value that grants the read ([RFC#0007]). While the flag is false, the `cnpg` plugin MUST report each local member `Unknown`, with role `unknown`, reason `PluginDisabled` and no declaration, and MUST NOT read. Checked by the unit tests `TestCNPGOff`, `TestCNPGOffReadsNothing`, `TestCNPGWatched` and `TestCNPGFlagFollowsValue`.

## `cnpg`: the role confirmed with the database

14. `spec.plugin.cnpg.confirmRole` MAY be true only with role `primary`. Unset or false turns it off. The CRD enforces it.
15. With `confirmRole` true, for each local member that requirement 9 and the tables below leave `Stable` with role `primary` or `replica`, the plugin MUST run `SELECT pg_is_in_recovery()` at each ready address of the `Cluster`'s `<cluster>-rw` Service, on that Service's target port. It MUST report the member `Unknown` with role `unknown` when any answer is `true` for role `primary` or `false` for role `replica`, with reason `RoleMismatch`, and when any check fails or the controller has no credentials, with reason `RoleNotConfirmed`. A member in any other state MUST NOT be checked. Checked by the unit test `TestCNPGConfirmRole`, and by the end-to-end `role-check` step.
16. The check MUST connect with TLS (`sslmode=require`, no fallback to plain text), as the role whose user name and password are in the controller's files, to the database `postgres`, and MUST end within 1s per address. The role MUST need `LOGIN` and nothing else. The controller MUST read the credentials from files at each check, and MUST NOT log or report the password. Checked by the unit test `TestPGRoleChecker`.
17. The chart MUST mount the Secret that `cnpg.confirmRole.secretName` names into the controller, read-only, and pass its directory as `--cnpg-role-credentials`. With the value empty, the controller MUST hold no database credential. Checked by the chart test `TestRoleCredentialsFollowValue`.

# Design

## Contract in code

```go
type Plugin interface {
	Observe(ctx context.Context, r client.Reader, svc *straitv1.SiteService, site string, now time.Time) observe.Report
}
```

The controller calls `Observe` on every reconcile of a `SiteService`, and on changes to the watched resources.

## `cnpg`: fields read

| Field | Use |
|---|---|
| `.spec.replica.self` | The cluster's own name in the distributed topology. Defaults to `.metadata.name`. |
| `.spec.replica.primary` | The declaration. |
| `.spec.replica.enabled` | Legacy replica clusters. When set, the cluster is a replica if true, and declares nothing. |
| `.spec.replica.promotionToken` | A promotion in progress, when it differs from `.status.lastPromotionToken`. |
| `.status.phase` | Transitioning phases. |
| `.status.currentPrimary`, `.status.targetPrimary` | A switchover inside the cluster, when they differ. |
| `.status.switchReplicaClusterStatus.inProgress` | A demotion in progress. |
| `.status.instancesReportedState[<currentPrimary>].isPrimary` | Whether the current primary instance is out of recovery, as the operator last polled it. The only status field that tracks writability; it lags the database by 1 to 3 seconds. |
| `Pooler` `.spec.cluster.name`, `.spec.type`, `.spec.pgbouncer.paused` | The Pooler belongs to the cluster, its type matches the role, and it is not paused. |

The declaration names a `Cluster` by its `self` name. The plugin maps it to the member whose `cnpg.cluster` has that name, so a `self` that differs from `.metadata.name` matches no member (requirement 7).

## `cnpg`: role and state

| Observed | Role | State |
|---|---|---|
| The plugin is off (requirement 13). | `unknown` | `Unknown` |
| The `Cluster` cannot be read. | `unknown` | `Unknown` |
| The `Cluster` does not exist. | `unknown` | `Stable`, not eligible |
| The `Cluster` is a replica cluster. | `replica` | per the table below |
| Otherwise. | `primary` | per the table below |

| Transitioning when | Reason |
|---|---|
| `.status.phase` is `Switchover in progress`, `Failing over`, `Promoting to primary cluster`, `Setting up primary`, `Primary instance is being restarted in-place`, `Primary instance is being restarted without a switchover` or `Applying configuration`. | `Phase: <phase>` |
| `.status.currentPrimary` differs from `.status.targetPrimary`. | `PrimaryChanging` |
| `.status.switchReplicaClusterStatus.inProgress` is true. | `Demoting` |
| `.spec.replica.promotionToken` is set and differs from `.status.lastPromotionToken`. | `Promoting` |
| The spec names the cluster primary, and the current primary instance is not reported out of recovery. | `NotYetWritable` |
| The spec names another cluster primary, and the current primary instance is still reported out of recovery. | `NotYetReadOnly` |

## `cnpg`: endpoint by role

| Role | Endpoint Service | Eligible when |
|---|---|---|
| `primary` | `<cluster>-rw`, or the `Pooler`'s Service | writable, and the Service has a ready address |
| `replica` | `<cluster>-ro` on a primary cluster, `<cluster>-r` on a replica cluster | `Stable`, and the Service has a ready address |
| `any` | `<cluster>-r` | `Stable`, and the Service has a ready address |

## `cnpg`: confirming the role

The `Cluster`'s status is CloudNativePG's view. It can lag behind the database, or be wrong. With `confirmRole`, the database itself must agree before a member counts.

| Database answer at every `-rw` address | Role from the `Cluster` | Member |
|---|---|---|
| `pg_is_in_recovery()` is `false` | `primary` | As the tables above say. |
| `true` | `replica` | As the tables above say. |
| Any other answer | either | `Unknown`, `RoleMismatch` |
| No answer within 1s, a refused login, or no credentials | either | `Unknown`, `RoleNotConfirmed` |

An `Unknown` member is never writable, and a routed one is held for `unknownHold` ([RFC#0002]).

What the check needs:

| Need | Value |
|---|---|
| A PostgreSQL role | `LOGIN` and nothing else. `pg_is_in_recovery()` runs for any role. For example, with CloudNativePG's managed roles: `spec.managed.roles: [{name: strait_role_check, login: true, passwordSecret: {name: ...}}]` on the primary cluster. Replica clusters get it by replication. |
| The database's access rules | The role may log in to the database `postgres` over TLS with a password, from the controller's pod. CloudNativePG's default rules allow it. |
| A Secret in the release namespace | Keys `username` and `password`. The chart value `cnpg.confirmRole.secretName` names it. Every site needs its own, for the same role. |
| Network | The controller's pod reaches each local `Cluster`'s pods on 5432. A NetworkPolicy in the database's namespace must allow it. |
| Time | One TLS connection and query per local member at each decision, which comes at least every 2s. All decisions share one worker ([RFC#0004]). |

# Security Considerations

- The controller's write permissions do not reach a plugin: a plugin receives a reader, and the RBAC rules for workload resources are read-only.
- Without `confirmRole`, the `cnpg` plugin never connects to PostgreSQL, and the controller holds no database credential.
- With `confirmRole`, the controller holds the password of one role with `LOGIN` and nothing else ([RFC#0007] requirement 9). The role can run read-only functions only. The password is read from a mounted file and never logged.
- `sslmode=require` encrypts but does not check the server's certificate. A party in the path could answer the query falsely. A false `true` or a failure only makes the member `Unknown`, so the route goes nowhere. A false `false` is no worse than the `Cluster`'s status alone. Password authentication is SCRAM by CloudNativePG's default, so the password is not sent.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| Plugins are compiled into the controller. | A plugin that must run out of process, or that a third party writes. |
| No plugin reads Valkey Sentinel's view of the primary. Apart from `confirmRole`, no plugin runs active checks (TCP, HTTP or SQL). | A user whose workload one of them would observe. |
| A routine configuration change also shows `Applying configuration`, so it routes nowhere for as long as CloudNativePG applies it. | A user whose configuration changes must not refuse connections. |
| A `cnpg` member and its `SiteService` share a namespace. | A user whose databases live in another namespace than the application. |
| A site whose local `Cluster`s name different primaries declares none to its peers, since the document holds one declaration per site ([RFC#0004]). Only its own decision routes nowhere for it. | A document version that carries more than one declaration per site. |
| A promotion restarts the new primary with a smart shutdown that waits up to `smartShutdownTimeout`, 180s by default, while sessions stay open. The `Cluster` reads `Transitioning` meanwhile, so Strait routes nowhere, even while a `Pooler` still takes writes. A short `smartShutdownTimeout` keeps the window short. | A user who needs writes during that window. |
