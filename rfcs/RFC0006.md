<h1 style="text-align: center;">[RFC#0006] CLI</h1>

# Abstract

`strait` is a read-only command line tool. It shows the state of a site, explains why an application name points where it does, and validates manifests before they are applied. One definition produces its help, its man pages and a skill document for AI agents.

# Overview

| Command | Shows |
|---|---|
| `strait status` | The local site with its controller's version, its peers in one line each, and every `SiteService` in the namespace, or in every namespace with `-A`, with its route and reason. |
| `strait explain SITESERVICE` | One `SiteService`: every member's observation, the path of each routed member, every site's declaration, the policy, the decision and its reason, the number of endpoints. With `-A`, the name must be unique across namespaces. |
| `strait links` | Every `SiteLink`: peer, transport, encryption, cost, endpoint-direct, health, and which link carries the pair's traffic. |
| `strait peers` | Every `SitePeer`: reachable or not, last successful poll, last error. |
| `strait validate -f PATH` | Checks manifests offline with the same rules the controller and the CRDs apply. |
| `strait --skill` | Prints the skill document. |
| `strait version` | The CLI's version and commit. `strait --version` prints them on one line. |

The same binary runs as `kubectl strait` when installed as `kubectl-strait`.

# Requirements

1. The CLI MUST NOT create, update, patch or delete any object. Its Kubernetes client MUST be typed as a reader with no write methods. Checked by review of `internal/cli/`.
2. Every command that reads a cluster MUST accept `--context` and `--kubeconfig`, and MUST use the context given, never a different one.
3. Commands that read namespaced objects MUST accept `-n/--namespace` and `-A/--all-namespaces`.
4. Every command MUST accept `-o table|json|yaml`. The default is `table`.
5. `strait validate` MUST NOT need a cluster. It MUST exit with status 1 and name the object and field of every violation.
6. `strait validate` MUST apply the same validation functions the controller applies. Checked by a test that runs both on the same fixtures.
7. `strait --skill` MUST print a document that starts with YAML frontmatter holding `name: strait` and a `description`, followed by Markdown. `strait --skill > <skills dir>/strait/SKILL.md` MUST install it.
8. The skill document MUST state what Strait is, how to read its state with each command, and that Strait never changes a workload.
9. The skill document, the man pages and `--help` MUST be generated from the command definitions. A test MUST fail if a command is missing from the skill document or the man pages.
10. The build MUST produce `strait(1)` and one man page per subcommand, and ship them with the binary in the image and in the release archive.
11. Exit status MUST be 0 on success, 1 on a validation error or a failed read, 2 on a usage error. Validation warnings alone exit 0.
12. `strait version` and `strait --version` MUST print the CLI's version and commit, and MUST NOT need a cluster. Checked by a test that runs both with no kubeconfig.
13. A binary built by `make build`, `make dist` or the `Dockerfile` MUST carry the version and the commit it was built from. Checked by `strait version` on the built binary.
14. The elected controller MUST write its version into `Site.status.controllerVersion`. `strait status` MUST show it on the site's line. Checked by the controller's test and the CLI's test.

# Design

## Global flags

| Flag | Default | Meaning |
|---|---|---|
| `--context` | the kubeconfig's current context | The kubeconfig context to read. |
| `--kubeconfig` | `$KUBECONFIG`, then `~/.kube/config` | The kubeconfig file. |
| `-n`, `--namespace` | the context's namespace | The namespace of namespaced objects. |
| `-A`, `--all-namespaces` | false | Every namespace. |
| `-o`, `--output` | `table` | `table`, `json` or `yaml`. |
| `--skill` | | Print the skill document and exit. |
| `--version` | | Print the CLI's version and commit on one line and exit. |

## One source

Each command is a `cobra.Command`. Its `Short`, `Long` and `Example` fields are the only place its documentation is written. A generator walks the command tree and writes:

| Output | How |
|---|---|
| `--help` | cobra. |
| Man pages | `cobra/doc`, one page per command, at build time. |
| Skill document | A template that holds the parts that are not per command (what Strait is, the rules) and walks the same tree for the rest. |

## Version

A binary takes each value from the first source that holds it.

| Value | Sources, in order |
|---|---|
| Version | `-X github.com/takodotid/strait/internal/version.Version` at build time. The module version in the Go build information, as `go install ...@vX.Y.Z` sets it. `dev`. |
| Commit | `-X github.com/takodotid/strait/internal/version.Commit` at build time. `vcs.revision` in the Go build information, with `-dirty` when `vcs.modified` is true. `unknown`. |

## `explain`

`explain` reads the `SiteService`'s status, written by the controller, and never re-runs the decision. The status already holds every input the decision used ([RFC#0002]), so the CLI shows the controller's view, not a second opinion that could differ.

# Implementation

| Path | Holds |
|---|---|
| `cmd/strait/` | The binary. |
| `internal/cli/` | The command tree, output formatting, the skill template. |
| `internal/version/` | The version and the commit of a binary. |
| `internal/controller/gateway_controller.go` | Writes `Site.status.controllerVersion`. |
| `internal/validate/` | Validation functions shared with the controller. |
| `hack/gendocs/` | Writes the man pages from the command tree. |
| `Makefile`, variables `VERSION` and `COMMIT` | The version and the commit that `build` and `dist` set, and that `images` passes to the `Dockerfile`. |
| `Makefile`, target `dist` | The release archive: `strait`, `kubectl-strait`, `man/man1/`, `SKILL.md`. |
| `Dockerfile` | The image ships the man pages in `/usr/share/man/man1`. Build arguments `VERSION` and `COMMIT`. |

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| `explain` covers one site per call. A view of every site needs one call per context. | Operators who need one view of all sites. |
| `validate` does not run the CRDs' CEL rules. It runs the Go validation functions, which hold the same rules. | A rule that exists only in CEL. |
| `strait status` shows the controller's version, not the gateway agent's. The chart runs both from one image. | A chart that runs them from different images. |
