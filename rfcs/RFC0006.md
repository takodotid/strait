<h1 style="text-align: center;">[RFC#0006] CLI</h1>

# Abstract

`strait` is a read-only command line tool. It shows the state of a site, explains why an application name points where it does, and validates manifests before they are applied. One definition produces its help, its man pages and a skill document for AI agents.

# Overview

| Command | Shows |
|---|---|
| `strait status` | The local site with its controller's version, its peers in one line each, and every `SiteService` in the namespace, or in every namespace with `-A`, with its route and reason. |
| `strait explain SITESERVICE` | One `SiteService`: every member's observation, the path of each routed member, every site's declaration, the policy, the decision and its reason, the number of endpoints. With `-A`, the name must be unique across namespaces. |
| `strait links` | Every `SiteLink`: peer, transport, encryption, cost, endpoint-direct and the ranges it accepts addresses from, health, and which link carries the pair's traffic. |
| `strait peers` | Every `SitePeer`: reachable or not, last successful poll, last error. |
| `strait validate -f PATH` | Checks manifests offline with the rules the CRDs apply, and checks the objects together. |
| `strait --skill` | Prints the skill document. |
| `strait version` | The CLI's version and commit. `strait --version` prints them on one line. |

The same binary runs as `kubectl strait` when installed as `kubectl-strait`, or `kubectl-strait.exe` on Windows.

# Motivation

| Reason | Choice |
|---|---|
| A review found that `strait validate` passed a `direct` link with `endpointDirect` and no `endpointCIDRs` with no sign. Endpoint-direct then writes any address from the peer's document that is not special ([RFC#0007], Limitations). | `strait validate` warns. |
| A review found that `hack/distcheck` checked neither `-trimpath` nor the VCS stamp of a binary. A binary built without `-trimpath` holds the paths of the build's machine, and one built from a changed tree is not the release's commit. Both still carry the version and the commit that the build's flags set. | `hack/distcheck` checks both. |
| A review found that `strait validate` skipped a document of kind `List`, as `kubectl get -o yaml` writes, and passed a `Site` with a lease duration of `0s`, which the API server refuses. A typed object cannot tell a field set to 0 from a missing one, so `strait validate` set the default on both. | `strait validate` reads the items of a `List`, and sets defaults from the fields that the document leaves out. |
| A rebuild of v1.3.0 from its tag gave the same files in every CLI archive, but other archive hashes. `tar` wrote the build's user, times and file-system order, and `hack/zipdir` the build's times. cobra dates each man page with the month of the build's clock, or of `SOURCE_DATE_EPOCH` in the build's time zone. A user who rebuilt an archive could compare its files, not its hash with `SHA256SUMS`. | `make dist` writes each archive from the commit's time, in name order, with no owner and fixed modes, and dates the man pages in UTC. `hack/distcheck` refuses an archive that differs. |

# Requirements

1. The CLI MUST NOT create, update, patch or delete any object. Its Kubernetes client MUST be typed as a reader with no write methods. Checked by review of `internal/cli/`.
2. Every command that reads a cluster MUST accept `--context` and `--kubeconfig`, and MUST use the context given, never a different one.
3. Commands that read namespaced objects MUST accept `-n/--namespace` and `-A/--all-namespaces`.
4. Every command MUST accept `-o table|json|yaml`. The default is `table`.
5. `strait validate` MUST NOT need a cluster. It MUST exit with status 1 and name the object and field of every violation.
6. `strait validate` MUST apply every validation rule of the CRDs, with the same message. Checked by a test that every rule of the CRDs has a fixture that `strait validate` rejects with the rule's message, and by `TestFixturesOnAPIServer`: a real API server rejects the same fixtures, names the same fields, and gives each rule's message.
7. `strait --skill` MUST print a document that starts with YAML frontmatter holding `name: strait` and a `description`, followed by Markdown. `strait --skill > <skills dir>/strait/SKILL.md` MUST install it.
8. The skill document MUST state what Strait is, how to read its state with each command, and that Strait never changes a workload.
9. The skill document, the man pages and `--help` MUST be generated from the command definitions. A test MUST fail if a command is missing from the skill document or the man pages.
10. The build MUST produce `strait(1)` and one man page per subcommand, and ship them with the binary in the image and in the release archive. Checked on each release by `hack/distcheck`: each archive and each platform of the image holds the man pages that `hack/gendocs` writes, and no other.
11. Exit status MUST be 0 on success, 1 on a validation error or a failed read, 2 on a usage error. Validation warnings alone exit 0.
12. `strait version` and `strait --version` MUST print the CLI's version and commit, and MUST NOT need a cluster. Checked by a test that runs both with no kubeconfig.
13. A binary built by `make build`, `make dist` or `make images` MUST carry the version and the commit it was built from. The `Dockerfile` MUST take both as the build arguments `VERSION` and `COMMIT`, since its build context holds no `.git`. Checked by `strait version` on the built binary. On each release, `hack/distcheck` checks that every binary of the archives and of the image holds both, and runs `strait version` of the `linux/amd64` archive and image.
14. The elected controller MUST write its version into `Site.status.controllerVersion`. `strait status` MUST show it on the site's line. Checked by the controller's test and the CLI's test.
15. Each release MUST publish a CLI archive, built by `make dist`, for `linux`, `darwin` and `windows`, each on `amd64` and `arm64`. Checked on each release by `hack/distcheck`, before anything is published: one archive per platform, no other, and binaries built for that platform.
16. Every CLI archive MUST hold one directory named after the archive, with `strait`, `kubectl-strait`, `man/man1/`, `SKILL.md`, `LICENSE` and `README.md`. On `windows` the binaries MUST be `strait.exe` and `kubectl-strait.exe` and the archive a `.zip`. Otherwise the archive MUST be a `.tar.gz`. Checked on each release by `hack/distcheck`, which lists each archive, and by its unit test `TestArchives`.
17. `make dist` MUST write the same archive, byte for byte, from one commit, one Go version and one `SOURCE_DATE_EPOCH`, whatever the build's time, time zone, umask and user. `SOURCE_DATE_EPOCH` MUST default to the commit's time, `git log -1 --format=%ct`. The entries MUST be sorted by name. Each entry MUST have the time `SOURCE_DATE_EPOCH`, and the mode 0755 for a directory or an executable, 0644 otherwise. In a `.tar.gz`, each entry MUST have the owner and group 0 with no names, and the gzip header MUST hold no name and no time. A `.zip` MUST store its times in UTC. Each man page MUST carry the month of `SOURCE_DATE_EPOCH` in UTC. The binaries MUST be built with `-trimpath` and with Go's VCS stamping, as `go version -m` on an archive's binary shows. Checked by the unit tests `TestWrite` and `TestReproducible` of `hack/archive` and `TestManDate` of `hack/gendocs`, and on each release by `hack/distcheck`, which refuses an entry that breaks this and names it (`TestArchiveEntries`).
18. `strait validate` MUST warn about each `direct` `SiteLink` with `endpointDirect: true` and no `endpointCIDRs`, on the field `spec.direct.endpointCIDRs`. Checked by the fixture `internal/validate/testdata/set/endpoint-cidrs.yaml`, through the unit tests `TestSet` and `TestValidateFixtures`.
19. `strait validate` MUST read a document of kind `List` of the core API group, and a list kind of Strait's API group, as each of its items, a `List` in it too. Each problem of an item MUST name its document and its path in it, such as `items[2]`. Checked by the unit test `TestValidateList`.
20. `strait validate` MUST set a default only on a field that the document leaves out or sets to null, as the API server does, and MUST check a field that the document sets as written, also when it holds 0, `0s` or an empty string. Checked by the unit test `TestValidateExplicitZero`, and by the bad fixtures `lease-duration-zero`, `service-type-empty`, `control-port-zero` and `multiple-empty` and the good fixture `service-without-type`, through `TestBad` and `TestFixturesOnAPIServer`.
21. Every binary of a CLI archive and of the image MUST be built with `-trimpath`. A binary that carries a VCS stamp, as a build in a git checkout adds, MUST name the release's commit, with no change to the tree. Checked on each release by `hack/distcheck`, in the jobs `test` and `image-check`, and by its unit test `TestImage`.

# Design

## Global flags

| Flag | Default | Meaning |
|---|---|---|
| `--context` | the kubeconfig's current context | The kubeconfig context to read. |
| `--kubeconfig` | `$KUBECONFIG`, then `~/.kube/config` | The kubeconfig file. |
| `-n`, `--namespace` | the context's namespace | The namespace of namespaced objects. |
| `-A`, `--all-namespaces` | false | Every namespace. |
| `-o`, `--output` | `table` | `table`, `json` or `yaml`. |
| `--skill` | | Print the skill document and exit. |
| `--version` | | Print the CLI's version and commit on one line and exit. |

## One source

Each command is a `cobra.Command`. Its `Short`, `Long` and `Example` fields are the only place its documentation is written. A generator walks the command tree and writes:

| Output | How |
|---|---|
| `--help` | cobra. |
| Man pages | `cobra/doc`, one page per command, at build time. |
| Skill document | A template that holds the parts that are not per command (what Strait is, the rules) and walks the same tree for the rest. |

## Version

A binary takes each value from the first source that holds it.

| Value | Sources, in order |
|---|---|
| Version | `-X github.com/takodotid/strait/internal/version.Version` at build time. The module version in the Go build information, as `go install ...@vX.Y.Z` sets it. `dev`. |
| Commit | `-X github.com/takodotid/strait/internal/version.Commit` at build time. `vcs.revision` in the Go build information, with `-dirty` when `vcs.modified` is true. `unknown`. |

## `explain`

`explain` reads the `SiteService`'s status, written by the controller, and never re-runs the decision. The status already holds every input the decision used ([RFC#0002]), so the CLI shows the controller's view, not a second opinion that could differ.

# Implementation

| Path | Holds |
|---|---|
| `cmd/strait/` | The binary. |
| `internal/cli/` | The command tree, output formatting, the skill template. |
| `internal/version/` | The version and the commit of a binary. |
| `internal/controller/gateway_controller.go` | Writes `Site.status.controllerVersion`. |
| `internal/validate/` | The validation functions of `strait validate`, which hold the CRDs' rules. |
| `hack/gendocs/` | Writes the man pages from the command tree, dated with `SOURCE_DATE_EPOCH` in UTC (requirement 17). |
| `Makefile`, variables `VERSION` and `COMMIT` | The version and the commit that `build` and `dist` set, and that `images` passes to the `Dockerfile`. |
| `Makefile`, target `dist` | The CLI archive of the platform that `GOOS` and `GOARCH` name. |
| `Makefile`, variable `SOURCE_DATE_EPOCH` | The time of the archive's entries and of the man pages: the commit's time, unless set (requirement 17). |
| `hack/archive/` | Writes the CLI archive, a `.zip` for `windows` and a `.tar.gz` otherwise (requirement 17). |
| `.github/workflows/release.yaml`, step `CLI archives` | The platforms each release builds an archive for. |
| `hack/distcheck/` | The check of the archives (requirements 10, 13, 15, 16, 17 and 21), of the image (requirements 10, 13 and 21), and of the image's index ([RFC#0007] requirement 30), which `release.yaml` runs in the jobs `test` and `image-check`. |
| `docs/runbooks/rebuild.md` | How to rebuild a release's CLI archive from its tag and compare it with `SHA256SUMS`. |
| `.github/workflows/release.yaml`, job `test`, step `The commit's time` | The `SOURCE_DATE_EPOCH` of `make dist` and `hack/distcheck`. |
| `Dockerfile` | The image ships the man pages in `/usr/share/man/man1`. Build arguments `VERSION` and `COMMIT`. |

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| `explain` covers one site per call. A view of every site needs one call per context. | Operators who need one view of all sites. |
| `validate` does not run the CRDs' CEL rules. It runs the Go validation functions, which hold the same rules. | A rule that exists only in CEL. |
| `strait status` shows the controller's version, not the gateway agent's. The chart runs both from one image. | A chart that runs them from different images. |
| On Windows, `kubectl strait` exits with status 1 on every failure, and kubectl adds the line `Error: exit status N`. kubectl runs a plugin there as a child process. `strait.exe` exits as requirement 11 says. | kubectl passes a plugin's exit status on Windows. |
| In Windows PowerShell 5.1, `strait --skill > SKILL.md` writes UTF-16LE, which breaks the frontmatter of requirement 7. The redirection re-encodes the output. The archive's `SKILL.md`, PowerShell 7 and `cmd.exe` keep it UTF-8. | A user who needs the skill document without the archive on Windows PowerShell 5.1. |
