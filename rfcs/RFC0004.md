<h1 style="text-align: center;">[RFC#0004] Observation Exchange</h1>

# Abstract

Each site publishes what it observes about its own members as a read-only document on its gateway. Each peer polls that document over a link. This is how a site learns the state of remote members, and how it detects two writable members or sites that declare different primaries.

# Overview

| Step | Where |
|---|---|
| The controller observes local members through plugins. | Local site |
| The controller serves the observation document. | Local site, behind the gateway's control port |
| Each peer's controller polls the document through its own gateway, over the lowest-cost healthy link. | Peer |
| The peer's controller uses the document as input to its decisions ([RFC#0002]). | Peer |

# Motivation

| Reason | Choice |
|---|---|
| Reading a remote member through another cluster's Kubernetes API needs credentials to that cluster, and a leak of them does more damage. | Each site observes only its own members, and shares only the result. No site holds credentials to another site's API. |
| Push needs a writable endpoint on every site. Poll needs only a read-only one. | Peers poll. The document is served for `GET` only. |
| Two clocks never agree exactly. | Freshness is measured on the reader's clock, from the time of the last successful poll. |
| A peer that cannot be read may still hold a writable primary. Treating it as having none would allow a second primary. | An unreachable peer is `Unknown`, never "no primary" and never `Multiple`. |
| Sites on different releases during an upgrade must still read each other's documents, and a reader rejects a document of another `apiVersion`. | The document and its path keep `strait.tako.id/v1alpha1`. They are versioned apart from the CRDs, which moved to `v1` ([RFC#0001]). |
| Nothing required readers to ignore unknown fields. Rejecting one, or dropping a field, would cut off sites on other releases during an upgrade or a rollback. | Within one `apiVersion`, a change to the document only adds optional fields, and a reader ignores what it does not know (requirement 17). |
| client-go releases the Lease after renewals fail for the renew deadline, but the manager stops runnables only later. A second controller could lead while the first's leader-only work still ran. | A controller that cannot renew the Lease leaves it held. Only a controller that stops on a termination signal releases it, once its leader-only work has stopped. |
| `SiteService` reconciles can hang while the document server and Lease stay healthy. Old observations then carry a new `generatedAt`; peers measure freshness from the poll and read them as fresh. | A site publishes a member as `Unknown` once its last observation is older than its `peerTimeout` (requirement 15). Each reconcile has a time limit. |
| Members are `Unknown` to peers while no controller serves. Without a release the next took the Lease 16 to 18s after starting: over half the default `unknownHold`, 30s ([RFC#0002]). | A controller that stops releases the Lease. |
| `observedAt` is set at each decision, so a peer's document differed at every poll. Each poll then requeued every `SiteService` and `Import` at the reader and rebuilt its gateway's configuration. | A reader ignores `generatedAt` and the members' `observedAt` when checking a peer's document for change, and keeps both as read (requirement 19). |
| A ping check passes a stuck poller or xDS loop. A check that waited for the API server or a link would restart a healthy controller while either is slow. | Liveness follows the poller's rounds and the xDS rebuild loop, which wait for neither. Work that waits for the API server shows in metrics instead ([RFC#0002] requirement 23). |
| An export's `ready` was published as last read, with no age, so an export reconcile that hangs would keep the export ready at the peers. | An export's `ready` is aged as members are, past the export's own refresh of 30s. |

- Document change check: the requeues came on top of the `SiteService` and `Import` own resync. Changing the document would change it for readers of other releases.
- Liveness check: a restart makes the other sites count this site's members `Unknown` until the next controller serves.

# Requirements

1. The controller MUST serve the document at `GET /v1alpha1/observations` and MUST refuse every other method with status 405.
2. The gateway MUST expose that path, and `GET /healthz`, on its control port to peers. It MUST NOT expose any other controller path.
3. The document MUST carry the site name, the generation time, and for every `SiteService` with a local member: each local member's observation and the site's declaration. It MUST also list the site's `Export`s with their gateway ports and readiness.
4. A site MUST report only its own members. A reader MUST ignore an observation whose member does not belong to the publishing site.
5. A reader MUST reject a document whose `site` is not the name of the `SitePeer` it polled, and MUST treat that peer as unreachable at once, without waiting for `peerTimeout`. It MUST also reject a document that lists a service, a member or an export twice.
6. A peer's controller MUST poll every peer every `Site.spec.exchange.pollInterval`. The default is 2s. Each request MUST time out within that interval.
7. A peer's document MUST be stale when the last successful poll is older than `Site.spec.exchange.peerTimeout`, measured on the reader's monotonic clock. The default is 6s. `peerTimeout` MUST be at least twice `pollInterval`.
8. While a peer's document is stale, every member at that peer MUST be `Unknown`, and that peer's declarations MUST be unknown.
9. A reader MUST reject a document larger than 4 MiB.
10. The poll MUST go through the local gateway, so it follows the same link choice as traffic. Checked by the unit test `TestPeerURL`, and by `TestBuildPeers` and `TestBuildClusters`, which route `/peers/<peer>/` to a cluster with the links' priorities of an import.
11. `SitePeer.status` MUST show whether the peer is reachable, the time of the last successful poll, and the last error.
12. A controller replica that is not elected MUST NOT serve the document or poll peers. It holds no observations, and an empty document would read as a site with no members. The controller runs as one replica with the `Recreate` strategy, and only the elected replica reports ready, so its Service never reaches a replica that is not elected. Checked by the unit test `TestRunnablesNeedLeaderElection`.
13. While a link to a peer is up, a change in the peer's document MUST show in the local site's decisions within `peerTimeout`. Checked by the end-to-end switchover test.
14. A controller that stops on a termination signal MUST release its leader election Lease once its reconcilers, its poller, its document server and its xDS server have stopped, and MUST exit right after. Checked by the unit test `TestStopReleasesLease`.
15. A site MUST publish a member as `Unknown`, with reason `ObservationStale`, no address and port 0, when its controller last observed the member longer before `generatedAt` than the greater of the site's `peerTimeout` and 6s, both on that controller's monotonic clock. A `peerTimeout` of 0s ages no member. The service's `declaredPrimary` MUST stay as last observed. A site MUST publish an export with `ready: false` and its port when its controller last read the export's readiness longer before `generatedAt` than 30s, the longest time between two such reads, and that limit together. Checked by the unit tests `TestDocumentAgesObservations`, `TestLocalDocumentAgesByPeerTimeout` and `TestDocumentAgesExports`.
16. A controller that stops leading because it could not renew its leader election Lease MUST NOT release the Lease. Checked by the unit test `TestLostLeaseNotReleased`.
17. Within one `apiVersion`, a change to the document MUST only add fields. It MUST NOT remove or rename a field, or change a field's type or meaning. A reader MUST ignore a field that it does not know, at every level of the document, and MUST accept a document that lacks a field added after the document's `apiVersion` was first served. Checked by the unit tests `TestReadDocumentWithUnknownFields` and `TestReadDocumentOfOtherReleases`, and by review of each change to `internal/exchange/document.go`.
18. The controller's liveness check MUST fail only while the elected controller's poll round or its xDS rebuild loop is overdue. The poll round is overdue when more than twice `pollInterval` and 30s have passed since the last round began. The xDS rebuild loop is overdue when more than twice its 2s period and 30s have passed since its last turn began. With polling off, the round's period is 1s. Both loops MUST read only the controller's cache, and each poll MUST time out within `pollInterval`, so that neither waits for the API server or a link. A controller that is not elected MUST pass. Checked by the unit tests `TestLivenessWhileAPIServerAndLinksHang`, with every write to the API server hung and a peer that never answers, and `TestLivenessFailsWhenALoopStops`.
19. A reader MUST count a peer's document as changed, and so requeue its decisions before their next resync, only when the document differs in a field other than `generatedAt` and the members' `observedAt`. It MUST keep the document as read, with both fields, for its decisions and its status. A decision MUST NOT depend on either field. Checked by the unit tests `TestChanged` and `TestNoChangeFromAPublisherAtRest`, and by review of `internal/decide/`.

# Design

## Document

```json
{
  "apiVersion": "strait.tako.id/v1alpha1",
  "kind": "Observations",
  "site": "a",
  "generatedAt": "2026-10-27T10:00:00Z",
  "services": [
    {
      "namespace": "app",
      "name": "pg",
      "declaredPrimary": "pg-a",
      "members": [
        {
          "name": "pg-a",
          "role": "primary",
          "eligible": true,
          "state": "Stable",
          "reason": "PrimaryCluster",
          "observedAt": "2026-10-27T10:00:00Z",
          "addresses": ["10.110.1.5"],
          "port": 5432
        }
      ]
    }
  ],
  "exports": [
    { "namespace": "app", "name": "pg-pg-a", "port": 30901, "ready": true }
  ]
}
```

| Field | Use at the reader |
|---|---|
| `generatedAt` | None. Freshness counts from the reader's last successful poll. |
| `services[].members[].observedAt` | `status.members[].observedTime` of the remote member ([RFC#0002]). |
| `services[].declaredPrimary` | Rows 1, 2 and 4 of the `Single` decision ([RFC#0002]). Empty when the site declares none. |
| `services[].members[]` | The remote member's observation. |
| `services[].members[].addresses`, `port` | Endpoint-direct only ([RFC#0005]). |
| `exports[]` | The remote port of each `Import` ([RFC#0005]). |

A service is matched across sites by namespace and name. A member is matched by name. A reader that finds a document changed, apart from `generatedAt` and `observedAt` (requirement 19), requeues the decision of every `SiteService` and the reconcile of every `Import` at once. Otherwise they run at their own resync; a `SiteService` decides at least every 2s ([Age of the publisher's observations](#age-of-the-publishers-observations)). Every release of `strait.tako.id/v1alpha1` reads every other's document (requirement 17).

## Age of the publisher's observations

| Subject | Value |
|---|---|
| Age limit | The publishing site's `peerTimeout`, at least 6s (requirement 15). |
| A member past it | `state: Unknown`, `role: unknown`, `eligible: false`, `reason: ObservationStale`, no address, port 0. `observedAt` keeps the time of the last observation. A reader routes it as any `Unknown` member ([RFC#0002]). |
| An export | Read at each change of its Service's EndpointSlices, and at least every 30s. Past 30s and the age limit together, published with `ready: false` and its port (requirement 15). |
| The service's `declaredPrimary` | Kept as last observed. Rows 1 and 4 of the `Single` decision only ever route nowhere, and a site that declares none takes no part in them ([RFC#0002]). |
| Time limit of each reconcile | 10s, the leader election's renew deadline. The status write after a decision has its own 5s ([RFC#0002] requirement 39). |

- Age limit: members are observed at each decision, at least every 2s, and every `SiteService`'s decisions share one worker. A shorter limit would age the members of a healthy site, as with the end-to-end test's `peerTimeout` of 3s.
- An export: its `ready` only sets the `Ready` condition of the peers' `Import`s; traffic follows the gateways' health checks ([RFC#0005]). Reading it every 2s would add an EndpointSlices read per export every 2s.
- Time limit of each reconcile: an API server that takes longer makes the controller lose the Lease anyway. The separate 5s lets status show a decision that ran out of time.

## Path through the gateway

```
controller (site b) -> gateway b, peer listener -> link -> gateway a, control port -> controller (site a)
```

The gateway's peer listener routes `/peers/<peer>/...` to that peer's control port over the link chosen as in [RFC#0005]. The controller never dials a link itself, so `wireguard` interfaces stay inside the gateway.

## Leader election

| Setting | Value |
|---|---|
| Lease | `strait-controller`, in the controller's namespace. |
| Lease duration, renew deadline, retry period | 15s, 10s, 2s. |
| A controller that stops on a termination signal | Waits for its leader-only work to stop, with no timeout of its own, then releases the Lease (requirement 14). The next controller takes it at its next try. |
| A controller that crashes, that the kubelet kills at the end of the pod's termination grace period, 30s, that stops on an error, or that cannot write the Lease | Leaves the Lease held. The next controller takes it 15s after it first reads it. |
| A controller that cannot renew the Lease within the renew deadline | Stops leading and exits without waiting for its leader-only work, leaving the Lease held (requirement 16). The next controller takes it 15s after it last saw it change. |

- A controller that cannot renew the Lease: the next controller takes the Lease at least 5s after this one stopped leading.

# Security Considerations

- The document holds member names, roles, states, and, for endpoint-direct, pod addresses. It holds no credentials.
- Over a `wireguard` link, only the holder of the peer's key can reach the control port. Over a `direct` link, the link is trusted by declaration ([RFC#0005], [RFC#0007]).
- A forged document could claim a second writable member, which routes nowhere, or hide one. Hiding one is the same risk as a partition, covered in [RFC#0002].
- A forged document could give endpoint-direct the address of something else in the reader's reach. The reader writes only the addresses that [RFC#0005] requirement 35 accepts.

# Limitations

| Limitation | What to do | Revisit when |
|---|---|---|
| No signature on the document. Integrity rests on the link. | Use `wireguard` links, or `direct` links over a network that is trusted and encrypted below Strait. | A transport without its own authentication. |
