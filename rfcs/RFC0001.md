<h1 style="text-align: center;">[RFC#0001] Scope and Glossary</h1>

# Abstract

Strait gives an application one local name per dependency, at every site, and points that name at the member that is active now. This RFC fixes what Strait is, what it is not, the resources it serves, and the words the other RFCs use.

# Overview

An application runs at two or more sites. Each site is one Kubernetes cluster, and every site serves traffic at the same time. The application depends on stateful services that have one leader, such as a PostgreSQL primary. The leader lives at one site and moves between sites when the operator or the workload's controller moves it.

Strait is a virtual service between those clusters:

- The application connects to one name, such as `pg.app.svc`, at every site.
- Strait observes where the active member is, through plugins, and shares what each site observes with the other sites.
- Strait writes that name's endpoints: the member's pods when the member is local, the local gateway when it is remote.
- The gateway carries TCP to the other site over a link.

Strait follows a move. It never makes one.

# Glossary

| Term | Meaning |
|---|---|
| Site | One Kubernetes cluster that runs Strait. Exactly one `Site` resource per cluster names it. |
| Peer | Another site this site exchanges observations and traffic with. One `SitePeer` per peer. |
| Link | One network path between this site and a peer, with a transport and a cost. One `SiteLink` per path. |
| Transport | How a link carries traffic: `direct` (a private path, no tunnel) or `wireguard` (an encrypted tunnel). |
| Gateway | The per-site proxy that carries traffic over links. |
| Proxy driver | The proxy software the gateway runs. Envoy in v1. |
| Member | One instance of a dependency at one site, for example one CloudNativePG `Cluster`. |
| Active member | A member that Strait routes to. One in `Single` mode, every eligible one in `Set` mode. |
| Application name | The local Service that an application connects to. One per `SiteService`. |
| Plugin | Code that reads a workload's state and reports per member: eligible, role, state, reason. |
| Observation | One plugin report about one member, with the time it was made. |
| Declaration | Which member a site's configuration names as primary. |
| Observation exchange | Each site publishes its observations; its peers poll them over a link. |
| Export | A local member made reachable to peers on a gateway port. |
| Import | A peer's export made reachable locally on a gateway port. |
| Route nowhere | The application name has no endpoints. A new connection is refused at once. |

# Motivation

| Constraint | Consequence |
|---|---|
| Pod traffic inside a cluster must keep its native performance. | Strait touches only the traffic of application names that point at another site. |
| One site may run a managed Kubernetes service whose CNI cannot be changed. | Strait does not need to own or replace the CNI. It runs as ordinary workloads. |
| A full service mesh costs too much in control plane and data plane. | Strait has no sidecars and no per-pod proxy. One gateway per site. |
| Applications must not hold topology: no host lists or address maps. | One stable local name per dependency. Infrastructure changes where it points. |
| Failover policy belongs to the workload. Two actors that fail over the same database fight. | Strait never acts on a workload. It observes and follows. |

# Requirements

1. Strait MUST NOT create, update, delete, promote, demote, pause or fence a workload's resources. Its permissions on workload resources MUST be `get`, `list` and `watch` only. Checked by review of the RBAC in the deploy manifests.
2. Strait MUST carry TCP only and MUST NOT parse an application protocol. Checked by review of the proxy configuration: TCP proxy filters only on application ports.
3. Strait MUST NOT route pod-to-pod traffic between clusters other than the traffic of an application name or an `Import`.
4. Strait MUST NOT route through a third site. Traffic between two sites uses a link between those two sites.
5. When Strait cannot tell which member is active, it MUST route nowhere, as defined in [RFC#0002].
6. Every behaviour MUST be set in a resource's spec, and every observation MUST show in a resource's status.
7. The API group MUST be `strait.tako.id`. The served version in v1 is `v1alpha1`.
8. A change to a served resource that breaks an existing user MUST be a new API version.

# Design

## Resources

| Kind | Scope | Purpose | Owner RFC |
|---|---|---|---|
| `Site` | Cluster | Names the local site. Gateway ports, WireGuard identity, exchange timing. | [RFC#0005] |
| `SitePeer` | Cluster | One peer site, and its WireGuard public key. | [RFC#0005] |
| `SiteLink` | Cluster | One path to a peer: transport, cost, addresses. | [RFC#0005] |
| `Export` | Namespaced | A local Service port offered to peers on the gateway. | [RFC#0005] |
| `Import` | Namespaced | A peer's export offered locally on the gateway. | [RFC#0005] |
| `SiteService` | Namespaced | The application name: members, mode, plugin, policy. | [RFC#0002] |

## Components

| Component | Runs as | Does |
|---|---|---|
| `strait-controller` | Deployment, one replica, `Recreate` strategy, leader election | Runs plugins, decides routes, writes application name endpoints, serves the observation document, serves xDS to the gateway. |
| `strait-gateway` | Deployment, one active replica | Envoy for traffic. An agent next to it holds WireGuard interfaces and reports link health. |
| `strait` | CLI | Reads Strait's resources and explains them. Read-only. |

# Limitations

| Not in v1 | Reason |
|---|---|
| Failover, switchover, promotion, fencing | Out of scope. The workload's controller or the operator does it. |
| Multi-hop routing, traffic weights, link capacity or bandwidth awareness | Out of scope. One link carries a pair's traffic at a time. |
| L7 routing | Out of scope. Strait carries TCP. |
| `PerMember` mode, every member under its own stable name | Needed for client-routed systems such as Kafka or Valkey Cluster. Deferred until a user needs it. |
| More than one port per `SiteService` | The v1 dependencies use one port each. |
