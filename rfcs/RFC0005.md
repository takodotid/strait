<h1 style="text-align: center;">[RFC#0005] Data Plane</h1>

# Abstract

The data plane carries the TCP traffic of application names between sites. Each site runs one gateway. Gateways are joined by links, each with a transport and a cost. This RFC fixes the link resources, the `direct` and `wireguard` transports, the gateway and its Envoy driver, health per export, link failover by cost, and endpoint-direct mode.

# Overview

```
site b                                                        site a
app -> pg.app.svc -> gateway b, import listener --link--> gateway a, export listener -> pg-a-rw -> primary
```

| Resource | Says |
|---|---|
| `Site` | This site's name, the gateway's ports, how peers reach them, the WireGuard private key's Secret. |
| `SitePeer` | A peer's name, its control port, its WireGuard public key. |
| `SiteLink` | One path to a peer: transport, cost, encryption, addresses. |
| `Export` | A local Service port that peers may reach, on a gateway port. |
| `Import` | A peer's export, offered locally on a gateway port, and on a Service of its own when `spec.port` is set. |

A `SiteService` creates its `Export`s and `Import`s ([RFC#0002]). They can also be written by hand to carry a plain TCP service between sites. A hand-written `Import` with `spec.port` gives that service a stable name at its site.

# Motivation

| Observed failure or reason | Choice |
|---|---|
| An inbound connection forwarded to the application name loops back over the link when the site is not active. | Inbound traffic always goes to the export's local Service. |
| Envoy spills traffic across priority levels when a level is partly healthy (default overprovisioning factor 1.4). A pair would use two links at once. | The overprovisioning factor is raised so one level takes all traffic while any of its endpoints is healthy. |
| Envoy's panic mode sends traffic to unhealthy endpoints when too few are healthy. | The panic threshold is 0. No healthy endpoint means the connection is closed at once. |
| A WireGuard key can be live in one place only. Two replicas that hold the same key reset each other's sessions. | One gateway replica is active at a time. The others are warm standbys. |
| Reloading a proxy to change endpoints drops or delays connections. | Envoy takes its configuration over xDS, with no reload. |
| A TCP check of a peer's export port succeeds while the peer's member is down, since the peer's Envoy accepts the connection. | Health per export is an HTTP check on the peer's control port, which answers from the export's endpoint health. |
| The peer's Envoy replaces its control listener whenever its exports change, and serves a connection opened before that with the old listener until it drains it. On kind, a connection opened before the peer added an export got 404 for that export's health path for about 16 seconds after the export was added, while a new connection got 200. A site can learn a new export's port from the peer's document before the peer's gateway has its health filter. In a test on kind that forced that order, a new import refused every connection for 10 to 38 seconds after the peer's filter was in place, and for 1.6 to 1.8 seconds with a new connection per check. In CI, a new import refused every connection for 30 seconds while its route showed `Active`; that this was the cause is inferred. | A check of an import opens a new connection each time. |
| In the benchmark, on two proxy hops, Envoy cost about 50 µs more per round trip than HAProxy and about 7% more CPU, and moved 1.7 to 2.6 times as much data at defaults. Against a cross-site round trip of 1 ms or more, 50 µs is 5% or less ([docs/benchmark.md](../docs/benchmark.md)). | Envoy is the proxy driver. |
| In the benchmark, when the gateway's node ran short of CPU, both proxies slowed down 35 to 40 times, far more than they differed. | The gateway's CPU request is set per site in the chart's values. |
| A `NodePort` or `LoadBalancer` Service opens its ports on every node address, public ones included. The direct Service carries the export ports in clear. | The direct Service is `ClusterIP` unless the operator sets it. A site with a `direct` link sets `NodePort` on nodes that no other network reaches, or an internal `LoadBalancer`. |
| Kubernetes accepts a node port only in the cluster's node port range, 30000-32767 by default, and each gateway node port equals its port. | The default WireGuard listen port is 31820, in that range. |
| Kernel WireGuard runs in the gateway pod's own network namespace with `NET_ADMIN` only. A userspace tunnel (wireguard-go with a netstack) needs no capability, but carried about a quarter of the kernel's throughput on one TCP stream in kind, and puts the agent in the data path. | Kernel WireGuard, created by the gateway agent through netlink. A userspace driver is a Limitation. |
| An import listener binds to the active gateway pod's address. That address changes at every handover: a rollout, a node drain, a node restart. A client that dials it breaks at the next one. | An `Import` with `spec.port` gets a Service named after it, whose endpoint follows the active gateway. |
| A cluster may require `loadBalancerSourceRanges` and `allocateLoadBalancerNodePorts: false` on every `LoadBalancer` Service, and reject the gateway Services without them. | The gateway Services take `loadBalancerSourceRanges`, `allocateLoadBalancerNodePorts` and `externalTrafficPolicy`. |
| The API server allocates a node port that a Service names, even with `allocateLoadBalancerNodePorts: false`. | With `allocateLoadBalancerNodePorts: false`, a gateway Service names no node port. |
| With `externalTrafficPolicy: Local`, kube-proxy and Cilium serve a Service only from the endpoints whose `nodeName` is their own node. An endpoint with no `nodeName` is local nowhere, so every connection is dropped. | The endpoint of a gateway Service names the active pod's node. |
| A review found that the controller compared the gateway Lease's `renewTime`, which the holder sets on its own node's clock, with the controller's clock, on a 6s Lease. With more than about 5s of skew between those two nodes, a live holder counts as expired, or a holder that stopped counts as live. The site then publishes no gateway address, which removes every remote route. | The controller times the Lease from when it saw it change, on its own monotonic clock, as client-go's leader election does. |
| A review found that an active gateway replica whose Envoy is not ready keeps the gateway Lease. Its pod is not ready, so the controller publishes no gateway address, and a ready standby cannot take over. A replica also joined the election before its Envoy was ready. | A replica joins the election only once its Envoy is ready. The active replica steps down after 6s of Envoy not ready, once its pod is not ready too. |
| The gateway Lease's timing was fixed: 6s duration, 4s renew deadline, 1s retry period. A review found that a stall of the API server longer than 4s would hand the gateway over, and reset every connection across the site's gateway. A longer Lease rides out a longer stall, and keeps a replica that failed active for longer. Which costs less depends on the site's API server. | The timing is a field of the `Site`. The defaults stay. |
| In a unit test, a replica that joined the election while its Envoy was ready took the Lease after its Envoy stopped being ready. It would step down 6s later. | A replica checks its Envoy before each write that takes the Lease. A renewal is not checked, so the active replica steps down after 6s of Envoy not ready, as requirement 34 says. |
| A review found that endpoint-direct copied member addresses from a peer's document into local EndpointSlices with no check, while the xDS path checks for an IP address. A compromised peer, or anyone on the path of a `direct` link, could point a local name at any address. | Endpoint-direct writes only IP addresses that are not special, and, with `direct.endpointCIDRs`, only the peer's ranges. Status names what it drops. |
| Two `Export`s, or two `Import`s, created together are reconciled one right after the other, before the controller's cache shows the port it gave the first. On kind, one `kubectl create` of 16 `Export`s left 6 ports held twice, and one of 16 `Import`s left 3. The gateway serves a shared port for one of its holders only, so the other's clients reach the wrong target. The API server refused the direct gateway Service with a node port twice, so that Service stopped taking new exports. | A port that the controller wrote counts as taken until its cache shows it. Of two holders of one port, the one that the gateway does not serve moves. |
| After a gateway handover at a site whose `wireguard` link waits for the peer to dial, traffic from the peer came back 15.6 to 16.7s after the takeover in a two-site test, and 15.8 to 17.7s on kind. On kind, `wg show` showed the peer sending on its session with the old replica and receiving nothing, and the new replica with no endpoint and no handshake, until the peer started a new handshake about 15s later. WireGuard starts one only after 15s of sending with no answer. The new replica cannot dial, since it does not know the peer's endpoint. A keepalive does not start a handshake. A handover at the dialing site recovered in 3.3s. | The dialing side drops a session whose peer sent nothing for 2s while it sent, and sends a packet through the link so that WireGuard starts a handshake at once. |
| A review inferred that a rollout of the gateway with 2 replicas could move the gateway Lease twice: the Deployment could delete the active pod first, and the other old pod take the Lease until it was deleted in turn. Each move resets every connection across the site's gateway. Among its pods that are equally ready, a ReplicaSet deletes those with the lowest `controller.kubernetes.io/pod-deletion-cost` first. | The active gateway pod has a deletion cost, and the standbys have none. A rollout deletes the active pod last. |
| On kind, the waiting site's NodePort sent the peer's packets to the new replica 0.4 to 3.0s after the takeover. A handshake sent before that is lost, and WireGuard sends the next one 5s later. | The dialing side drops the session again each second while the peer stays silent. A link whose round trip exceeds the health check's timeout of 500ms is never healthy, so an answer comes well within a second. |
| A review found that the controller ignored the error that Envoy sends with a rejected configuration. Envoy keeps the configuration it accepted last, so the gateway could miss the latest routes while status showed them. | The controller logs and counts each rejection, and the `Site`'s `GatewayConfig` condition names it. |
| In a unit test, and with a real Envoy, the controller's xDS library answered a rejection at once with the configuration just rejected: a rejection names the version that Envoy accepted last, and the library sends the cache's version whenever the two differ. Envoy rejected it again, in a loop with no pause, until the configuration changed. | After a rejection, the controller sends that type again only once the configuration changes. |
| A review found no metric of the data plane: no connections, bytes or connect failures per link, export or import. Envoy's admin interface, which has them, is on 127.0.0.1 only. | The gateway agent serves its own metrics, and a filtered copy of Envoy's stats, on a port of its own. |
| In a real Envoy, the stats of an `Export` whose name held a dot split at the dot: Envoy's labels ended the cluster's name there, and put the rest into the metric's name. Envoy labels a listener's stats with its address and port. | The stat name of a cluster and a TCP proxy has `_` for each dot. The agent leaves out the listeners' stats: the TCP proxies' stats count the same connections and bytes. |
| A review found that the gateway agent's liveness probe always passed, that Envoy had none, that a link failing over logged at V(1) only, and that a handover of the gateway Lease left no trace. Envoy's admin interface is on 127.0.0.1 only, and its image has no shell. A probe of Envoy through the agent would restart a healthy Envoy, and move the Lease, whenever the agent restarts. | The agent's liveness follows its session loop, which waits only for the kernel. Envoy's own watchdog kills a stuck Envoy. Link changes log at the info level, and each handover is an event on the `Site`. |
| A review found that each reconcile of an `Export` or an `Import`, every 30s and at each change, listed and copied every object of its kind from the cache to check one port. The cost grows with the square of the count. | To keep a port, the controller reads only the objects that hold it. |
| A review found that a change of any EndpointSlice of the cluster, and each renewal of a Lease in the controller's namespace, rebuilt the gateway's configuration at once. The configuration reads no Lease, and only the EndpointSlices of the Services that `Export`s forward to. In a large cluster, EndpointSlices change all the time. | The controller rebuilds the configuration at once only when one of its inputs changes: the `Site`, a `SitePeer`, a `SiteLink`, an `Export`, an `Import`, an EndpointSlice of a Service that an `Export` forwards to, or a pod of the controller's namespace. Any other change waits for the rebuild that comes every 2s ([RFC#0004] requirement 18). |
| A two-site test reported a `SiteService` with the condition `Routed` `False` for 0.34s during a gateway rollout, while its route stayed `Active`. Between the old replica's release of the Lease and the new replica's takeover, no replica can carry the traffic. The old replica's address would be a guess. | A member reached through the gateway has no endpoint while no replica is active, and status says so. |

# Requirements

## Links

1. A `SiteLink` MUST name one `SitePeer`, one transport and a cost between 0 and 65535.
2. Among the healthy links to a peer, traffic MUST use the one with the lowest cost, then the lowest name. Other links MUST carry no new connection while it is healthy.
3. A link MUST count as healthy while the peer's control port answers `GET /healthz` over it. A link that fails two checks in a row, one second apart, MUST count as unhealthy. A check fails when no answer arrives within 500ms.
4. When the active link becomes unhealthy, new connections MUST use the next healthy link within 5 seconds. Checked by the end-to-end `2-link-failover` step: every new connection that starts 5s or more after the direct link is cut reaches the member over the next link.
5. `SiteLink.status` MUST show whether the link is healthy and whether it is the active link.

## Transports

6. A `direct` link MUST carry traffic to the peer gateway's address on the link with no tunnel, and MUST declare `encryption: None`.
7. A `wireguard` link MUST carry traffic in a WireGuard tunnel between the two gateways, keyed by the `Site`'s private key and the `SitePeer`'s public key.
8. A `wireguard` link with an `endpoint` MUST dial it and send keepalives. A link without one MUST wait for the peer to dial. Traffic MUST flow both ways once the peer has dialed.
9. Each `wireguard` link MUST have its own interface in the gateway pod's network namespace, and MUST NOT change any route or interface outside it.

## Gateway

10. The gateway MUST run as a Deployment with a configurable number of replicas. Exactly one replica, the holder of the `strait-gateway` Lease, MUST be active. A standby replica MUST NOT hold WireGuard interfaces.
11. The gateway Services and the remote endpoints of application names MUST point at the active replica only.
12. The proxy driver in v1 MUST be Envoy, configured over ADS by the elected controller. An endpoint change MUST NOT restart or reload Envoy.
13. Every export MUST have its own listener on its gateway port, and MUST forward only to its local Service's ready endpoints.
14. Every import MUST have its own listener on its gateway port, bound to the gateway pod's address, and MUST forward to the peer's export over the active link.
15. Each import's cluster MUST have one priority level per link to the peer, ordered by requirement 2, with an overprovisioning factor of at least 100000 and a panic threshold of 0.
16. The control port MUST answer `GET /healthz/exports/<namespace>/<name>` with 200 while the export has a healthy endpoint, and 503 otherwise.
17. An import's endpoint on a link MUST count as healthy only while the peer answers 200 for that export over that link. Each check MUST open a new connection.

18. A link's peer address MUST be an IP address: `direct.address` and `wireguard.peerAddress`. Envoy's EDS takes IP addresses only. `wireguard.endpoint` MAY be a host name; the gateway agent resolves it.

## Endpoint-direct

19. Endpoint-direct MUST apply only to a `direct` link with `endpointDirect: true`, and only while that link is the active, healthy link to the peer. Checked by the unit test `TestEndpointDirectOnlyOnTheActiveHealthyLink`.
20. While it applies, the endpoints of an application name for a member at that peer MUST be the member's own addresses and port from the peer's document ([RFC#0004]).

## Gateway Services

21. `Site.spec.gateway.directService` and `wireGuardService` MAY set `loadBalancerSourceRanges` and `allocateLoadBalancerNodePorts` with `type: LoadBalancer` only, and `externalTrafficPolicy` with `type: NodePort` or `LoadBalancer` only. The CRD MUST reject such a field when that `type` is not set in the same object.
22. The controller MUST copy each of these fields that is set onto its gateway Service. A field that is unset MUST leave the Service as the API server defaults it: `externalTrafficPolicy: Cluster` on `NodePort` and `LoadBalancer`, `allocateLoadBalancerNodePorts: true` on `LoadBalancer`, no source range. The controller MUST clear from the Service a field that does not apply to its type.
23. With `NodePort` or `LoadBalancer`, each node port of a gateway Service MUST equal its port. With `allocateLoadBalancerNodePorts: false`, a gateway Service MUST name no node port. A gateway Service and its EndpointSlice MUST list each port once, also when two `Export`s hold one port. Checked by the unit test `TestDirectServiceListsEachPortOnce`.
24. The endpoint of each gateway Service MUST carry the active pod's node name. Its EndpointSlice MUST have the address type of the active pod's address: a slice of the other family is deleted and written again. Checked by the unit tests `TestGatewayEndpointNamesItsNode` and `TestGatewaySliceFollowsTheAddressFamily`.

## Import Services

25. An `Import` MAY set `spec.port`: one TCP port and its name. A `SiteService` MUST NOT set it on the `Import`s it creates. With `spec.port` set, the CRD MUST reject an `Import` whose name is not a DNS-1035 label.
26. With `spec.port` set, the controller MUST write a Service named after the `Import`, in its namespace, of type `ClusterIP`, with no selector and that one port, and MUST own it. If a Service of that name exists and another owner holds it, the controller MUST NOT change it and MUST report the conflict in the `Import`'s status.
27. The controller MUST write that Service's endpoints as one EndpointSlice named after the `Import`, labelled `kubernetes.io/service-name` and `endpointslice.kubernetes.io/managed-by: strait.tako.id`, and owned by the `Import`. Its endpoint MUST be the active gateway's address on the `Import`'s gateway port. With no active gateway or no allocated port, it MUST have no endpoint.
28. A change of `Site.status.gateway` MUST trigger the rewrite of that EndpointSlice, with no wait for a periodic resync.
29. Without `spec.port`, the controller MUST delete the Service and the EndpointSlice that the `Import` owns. It MUST NOT delete one that the `Import` does not own.

## Gateway ports

30. Each `Export` MUST hold a gateway port from `Site.spec.gateway.exportPorts` that no other `Export` holds, and each `Import` one from `importPorts` that no other `Import` holds, also when they are created together. With no free port in its range, an object MUST hold none, and its `Allocated` condition MUST be `False` with reason `RangeFull`.
31. An object MUST keep its port while the port is in its range and no other object of its kind that comes first holds it. Of two objects that hold one port, the one with the lower namespace, then the lower name, comes first: the gateway serves that one only. The other MUST get a new port at its next reconcile.

## Gateway Lease

32. The controller MUST count the `strait-gateway` Lease as expired once its spec has not changed for `leaseDurationSeconds`, timed on the controller's monotonic clock from when the controller saw the spec change. It MUST NOT compare `renewTime` with its own clock. Checked by a unit test with the holder's clock an hour behind and an hour ahead.
33. A gateway replica MUST join the election for the `strait-gateway` Lease only once its Envoy's admin `/ready` answers 200 within 1s: when it starts, and again after each step-down. It MUST also make this check before each write that takes the Lease, as opposed to one that renews it, and MUST NOT take the Lease when the check fails. Checked by the unit tests `TestJoinOnlyWhenEnvoyReady`, `TestNoTakeoverWhileEnvoyNotReady` and `TestLeaseChecksReadinessOnlyToTake`.
34. The active replica MUST step down, remove its WireGuard interfaces and release the Lease once its Envoy has not been ready for 6s. Checked by a unit test, and by the end-to-end `envoy-not-ready` step.

## Endpoint-direct addresses

35. Endpoint-direct MUST write only the member addresses from the peer's document that are IP addresses and are not unspecified, loopback, link-local or multicast. When the link sets `direct.endpointCIDRs`, it MUST write only the addresses in those ranges. It MUST NOT write a port outside 1 to 65535. A member with no address left takes the gateway, as a member whose document gives no address does.
36. For each routed member, the message of the `Routed` condition ([RFC#0002]) MUST name the addresses that requirement 35 drops, and why: at most 5 per member, each cut to 64 bytes, and the count of the others.

## WireGuard sessions

37. The active replica MUST drop the WireGuard session of a `wireguard` link with an `endpoint` once the peer has sent nothing on it for 2s while the replica sent, and again each second while the peer stays silent. It MUST drop it in one change that keeps the peer's endpoint, allowed IP and keepalive, and MUST then send a packet to `wireguard.peerAddress`. It MUST NOT drop the session of a link without an `endpoint`. Checked by unit tests, and by the end-to-end `gateway-handover` step.

## Gateway Lease timing

38. The gateway Lease's duration, renew deadline and retry period MUST be those of `Site.spec.gateway.lease`: 6s, 4s and 1s by default. A replica MUST read them each time it joins the election. The CRD MUST reject a duration outside 2s to 5m or not a whole number of seconds, a renew deadline under 1s, a renew deadline that is not at least 1s shorter than the duration or not more than 1.2 times the retry period, and a retry period under 200ms. Checked by the unit tests `TestLeaseTimingRidesOutAStall` and `TestLeaseTimingDefaults`, and by `TestFixturesOnAPIServer`.

## Gateway rollouts

39. The controller MUST set the annotation `controller.kubernetes.io/pod-deletion-cost` to `1` on the gateway pod that holds the gateway Lease while the Lease is valid (requirement 32), and MUST remove it from every other gateway pod. A gateway pod is a pod of the controller's namespace labelled `app.kubernetes.io/name: strait` and `app.kubernetes.io/component: gateway`. The controller MUST NOT change anything else on a pod. Checked by the unit test `TestDeletionCostOnTheActivePod`, and by the end-to-end `gateway-rollout` step, which counts the moves of the Lease in one rollout.

## Configuration rejections

40. A gateway Envoy rejects a configuration with an xDS request that carries an error and the nonce of the last response of that type. The controller MUST then log the pod, the type and Envoy's error, MUST count the rejection in the metric `strait_xds_rejected_total`, and MUST set the `Site`'s condition `GatewayConfig` to `False` with reason `Rejected`, and a message that names the pod, the type and the error. The condition MUST be `True` with reason `Accepted` once each pod has accepted a later configuration of each type it rejected, or has closed its last stream. Checked by the unit tests `TestRejections` and `TestGatewayConfigCondition`, and by `TestEnvoyRejection` in a real Envoy.
41. After a rejection, the controller MUST NOT send that pod that type again until the pod's configuration changes. Checked by `TestRejections` and `TestEnvoyRejection`.

## Observability

42. The gateway agent MUST serve its metrics at `GET /metrics`, and Envoy's stats at `GET /stats/prometheus`, on its metrics port, bound to the pod's own address ([RFC#0007] requirement 12). It MUST pass to Envoy's admin interface only `GET /stats/prometheus`, with the filter `gateway.EnvoyStats`, which leaves out every stat whose labels hold an address or a port. Checked by the unit test `TestMetricsPaths`, and by `TestEnvoyStatsLabels` in a real Envoy.
43. The stat name of a cluster or a TCP proxy MUST be its name with each dot as `_`. A cluster whose name holds no dot MUST have no `alt_stat_name`. Checked by the unit test `TestBuildStatNames`, and by `TestEnvoyStatsLabels`.
44. The gateway agent's liveness check MUST fail only while the active replica's WireGuard session loop has not finished a turn for 30s. That loop MUST wait for nothing but the kernel. A standby replica MUST pass. Checked by the unit tests `TestAgentAliveWhileAPIServerAndEnvoyHang`, with every write to the API server and Envoy's `/clusters` hung, and `TestAgentAliveFailsWhenTheKernelHangs`.
45. Envoy's bootstrap MUST set a watchdog `kill_timeout` of 60s on the main thread and on the workers. Checked by the unit test `TestBootstrapFile`, and by `TestEnvoyValidate` in a real Envoy.
46. The controller MUST record an event on the `Site` at each change of the pod that holds the gateway Lease, as `Site.status.gateway.activePod` shows it: `Normal`, reason `GatewayHandover`, when a pod holds it, and `Warning` when none does. A controller that starts and finds the pod that status names MUST record none. Checked by the unit test `TestGatewayHandoverEvents`.
47. The gateway agent MUST log at the info level each change of a link's `healthy` or `active`. Checked by the unit test `TestLinkChangesLogAtInfo`.

# Design

## Gateway pod

| Container | Does |
|---|---|
| `envoy` | Carries traffic. Configuration from the controller over ADS. Node ID is the pod name. |
| `agent` | Joins the Lease's election once Envoy is ready. While active: creates the WireGuard interfaces, publishes the public key, reports link health from Envoy's admin interface. |

Standby replicas run Envoy with the same configuration, so a new active replica only needs its WireGuard interfaces. The controller reads the Lease to find the active pod.

## Ports

| Port | Bound to | Reached by | Serves |
|---|---|---|---|
| `Site.spec.gateway.controlPort` (30900) | all addresses | peers | `/healthz`, `/healthz/exports/...`, `/v1alpha1/observations` |
| `Site.spec.gateway.exportPorts` (30901-31899) | all addresses | peers | One export each. |
| `Site.spec.gateway.importPorts` (15000-15999) | pod address | local pods | One import each. |
| `Site.spec.gateway.peerPort` (14999) | pod address | the controller | `/peers/<peer>/...` to each peer's control port. |
| `SiteLink.spec.wireguard.listenPort` (31820) | all addresses, UDP | peers | WireGuard. |

Each `Export` and each `Import` holds one port of its range in `status.gatewayPort` (requirements 30 and 31):

| Case | Port |
|---|---|
| A new object, or one whose port is outside its range | The lowest port of the range that no other object of its kind holds. None, with `RangeFull`, when there is no such port. |
| Its port is in its range, and no other object that comes first holds it | Kept. |
| Another object that comes first holds its port | A new one, as for a new object. The controller logs `gateway port moved`. |

The controller reads the other objects' ports from its cache. For an object whose last status write the cache does not show yet, the port of that write counts. To keep an object's port, the controller reads only the objects that hold that port, through an index of its cache by `status.gatewayPort`. It lists every object of the kind only to give a port. The controller reconciles every object when it starts, so a port that an earlier release or an earlier leader gave twice moves then.

The controller keeps two Services that point at the active replica:

| Service | Ports | Exposure |
|---|---|---|
| `strait-gateway-direct` | control, every export | `Site.spec.gateway.directService`: `ClusterIP` by default; `NodePort` or `LoadBalancer` on the private link only |
| `strait-gateway-wireguard` | every WireGuard listen port | `Site.spec.gateway.wireGuardService`: `NodePort` by default |

With `NodePort` or `LoadBalancer`, each node port equals its port, so the same port number reaches a gateway on every path, and each port must be in the cluster's node port range. A `LoadBalancer` with `allocateLoadBalancerNodePorts: false` has no node port.

| `ServiceExposure` field | Applies to type | Sets on the Service |
|---|---|---|
| `type` | any | The type. Unset: the default in the table above. |
| `annotations` | any | Its annotations, for example to make a load balancer internal. |
| `loadBalancerSourceRanges` | `LoadBalancer` | The client CIDRs that the load balancer admits. |
| `allocateLoadBalancerNodePorts` | `LoadBalancer` | `false`: no node port. |
| `externalTrafficPolicy` | `NodePort`, `LoadBalancer` | `Local`: the client's address is kept, and only the node of the active gateway serves the Service. |

The sources that must reach the gateway Services, and how to admit only them: [RFC#0007].

## Import Services

| Object | Name | Shape |
|---|---|---|
| Service | The `Import`'s | `ClusterIP`, no selector. One TCP port: `spec.port`. Owned by the `Import`. |
| EndpointSlice | The `Import`'s | The active gateway pod's address, on the `Import`'s `status.gatewayPort`, in a port named `spec.port.name`. Owned by the `Import`. |

The `Service` condition of an `Import` exists only while `spec.port` is set:

| Status, reason | Means |
|---|---|
| True, `Synced` | The Service and its EndpointSlice are written. |
| False, `ServiceConflict` | A Service of that name exists, and Strait does not own it. |
| False, `SyncFailed` | A write failed: the API server refused it, or the controller does not write in the `Import`'s namespace ([RFC#0007] requirement 16). The message holds the error. |

## Envoy configuration

| Object | Name | Shape |
|---|---|---|
| Listener | `export/<ns>/<name>` | TCP proxy to cluster `export/<ns>/<name>`. |
| Cluster | `export/<ns>/<name>` | EDS: the ready endpoints of the export's Service, on its target port. |
| Listener | `import/<ns>/<name>` | TCP proxy to cluster `import/<ns>/<name>`. |
| Cluster | `import/<ns>/<name>` | EDS: one endpoint per link, at the link's peer address and the export's remote port. Priority by link rank. HTTP health check on the peer's control port, path `/healthz/exports/<ns>/<export>`. |
| Listener | `control` | HTTP. One health check filter per export, with `cluster_min_healthy_percentages` on `export/<ns>/<name>`. Routes `/healthz` to a direct 200, `GET /v1alpha1/observations` to the controller. Everything else 404. |
| Listener | `peers` | HTTP. Route prefix `/peers/<peer>/` to cluster `peer/<peer>`, prefix rewritten to `/`. |
| Cluster | `peer/<peer>` | EDS: one endpoint per link at the peer's control port. Priority by link rank. HTTP health check `/healthz`. |
| Cluster | `controller` | The controller's Service, observation port. |

| Setting | Value | Why |
|---|---|---|
| Health check interval, timeout | 1s, 500ms | Requirement 4. The next check starts one interval after the last one ends, so a dead path is marked unhealthy within 3s. |
| Unhealthy threshold, healthy threshold | 2, 2 | One lost packet does not fail a link over. |
| Health check `reuse_connection` | `false` for an import, the default `true` for a peer | Requirement 17. A peer's `/healthz` answers the same in every version of its control listener. |
| `ClusterLoadAssignment.policy.overprovisioning_factor` | 100000 | Requirement 15. |
| `common_lb_config.healthy_panic_threshold` | 0 | Requirement 15. |
| Health check filter minimum healthy percentage | 1 | Envoy truncates it to an integer, and 0 lets an empty cluster pass. With up to 100 endpoints, any one healthy endpoint is enough. |
| TCP proxy `idle_timeout` | 0, disabled | Pooled database connections stay idle for hours. Envoy's default of 1 hour would cut them. |
| Upstream TCP keepalive | 30s, then every 5s, 3 probes | Finds a connection whose link died, since the idle timeout no longer does. |
| ADS port of the controller | 18000 | |

The link address is `direct.address` for a `direct` link and `wireguard.peerAddress` for a `wireguard` link.

## Configuration rejections

| `GatewayConfig` status, reason | Means |
|---|---|
| True, `Accepted` | No connected gateway pod holds a rejection. |
| False, `Rejected` | A gateway pod rejected its last configuration of a type, and runs the one it accepted last. The message names up to 5 rejections, each cut to 256 bytes, then the count of the others. |

A rejection that changes nothing in the configuration stays until the configuration changes, for example when an `Export`, an `Import` or a link changes. The controller's log holds every rejection, with the versions rejected and accepted.

## WireGuard

| Setting | Value |
|---|---|
| Interface name | `st` and the first 8 hex digits of the FNV-1a hash of the `SiteLink`'s name. |
| Private key | The Secret named by `Site.spec.wireguard.privateKeySecretRef`, in the gateway's namespace. |
| Peer public key | `SitePeer.spec.wireguard.publicKey`. |
| Allowed IPs | `wireguard.peerAddress`, as a /32 or /128. |
| Address | `wireguard.address`, on the interface. |
| Keepalive | `wireguard.persistentKeepalive`, only when `endpoint` is set. |
| Stale session | Only when `endpoint` is set. The agent reads the peer's counters every 250ms. Once the peer has sent nothing for 2s while the gateway sent, the agent replaces the peer with the same settings, which drops its session, and sends one empty UDP datagram to `peerAddress` on port 9. WireGuard sends a handshake at once, and the peer drops the datagram. While the peer stays silent, the agent does it again each second (requirement 37). |

The host's kernel MUST provide the `wireguard` module. The gateway agent does not load it.

## Endpoint-direct

| `SiteLink.spec.direct` field | Sets |
|---|---|
| `endpointDirect` | `true`: while this link is the active, healthy link to the peer, application names point at the peer's member addresses, with no gateway hop. |
| `endpointCIDRs` | Up to 16 CIDRs, such as the peer's pod CIDRs. Endpoint-direct writes only the member addresses in them. Empty accepts any address that requirement 35 accepts. |

## Timing of the gateway Lease

| `Site.spec.gateway.lease` field | Default | Sets |
|---|---|---|
| `duration` | 6s | How long the Lease stays valid after it last changed. A replica that failed stays active for up to this long. |
| `renewDeadline` | 4s | How long the active replica tries to renew the Lease before it steps down: it removes its WireGuard interfaces and releases the Lease. A stall of the API server longer than this hands the gateway over, and resets every connection across the site's gateway. |
| `retryPeriod` | 1s | The time between two tries to take or renew the Lease. |

| Rule | Why |
|---|---|
| `renewDeadline` at least 1s shorter than `duration` | The active replica removes its interfaces before another replica can take the Lease. |
| `renewDeadline` more than 1.2 times `retryPeriod` | client-go's leader election refuses less. |
| `duration` in whole seconds | The Lease holds it in whole seconds. |

A replica reads the timing when it joins the election (requirement 38). A change reaches the active replica at its next step-down or restart, such as the next gateway rollout. The controller and the standbys time the Lease by the `leaseDurationSeconds` that the holder wrote. The 6s after which the active replica steps down when its Envoy is not ready (requirement 34) is apart from this timing: it matches Envoy's readiness probe.

## Failover sequence

| Time | Event |
|---|---|
| 0s | The `direct` path to the peer fails. |
| up to 3s | Two health checks fail. Envoy marks the `direct` endpoints of every `peer/` and `import/` cluster unhealthy. |
| at once | New connections use the next priority, the `wireguard` link. Connections on the failed path end with it. |
| next agent poll, 1s | `SiteLink.status` shows the change. |

| Time | Event, when the active gateway replica fails |
|---|---|
| 0s | The active replica stops renewing the `strait-gateway` Lease. A replica that is shutting down releases it at once. |
| from then until a standby takes the Lease | No replica is active, so each `SiteService` member reached through the gateway has no endpoint (requirement 11), as the paragraph below says of the gateway Services. A `SiteService` whose route holds only such members keeps its route and its reason, with `status.route.endpoints` 0 and the condition `Routed` `False`, reason `NoEndpoints` ([RFC#0002], requirement 27). A reader that polls `SiteService` conditions can see it. Checked by the unit test `TestGatewayHandoverLeavesNoEndpoint`. |
| up to `lease.duration`, 6s by default | The Lease expires. A standby takes it and creates the WireGuard interfaces. The controller counts the duration from when it last saw the Lease change (requirement 32), and looks again when it ends. |
| after a release instead: up to `lease.retryPeriod`, 1s by default | A standby takes the Lease at its next try, and creates the WireGuard interfaces. |
| at once | The controller points the gateway Services, the remote endpoints and the `Import` Services at the new replica. kube-proxy, or the CNI, applies the change to the gateway Services after its own sync delay. |
| about 2s more | Envoy's health checks pass twice on the new replica's links. A `wireguard` link with an `endpoint` handshakes at the first packet. A `wireguard` link without one waits for the peer to dial. |
| 2s after the old replica's interfaces are gone | A peer that dials a `wireguard` link of this site drops its session and sends a handshake (requirement 37). It does so each second until the site's WireGuard Service reaches the new replica. Then the peer's checks pass twice. |

The controller writes each state of the Lease as it sees it. When the active pod starts to terminate, or releases the Lease, the gateway Services lose their endpoint: no replica is active (requirement 11). They get the new replica's endpoint when a standby takes the Lease. So a takeover after a release writes the endpoints twice, about one `lease.retryPeriod` apart, and never names two pods.

| Time | Event, when the active replica's Envoy is not ready |
|---|---|
| 0s | Envoy stops answering `/ready` with 200, for example while it restarts or starves for CPU. |
| 4s to 6s | The pod's readiness probe, 3 failures 2s apart, marks the pod not ready. The controller stops publishing it. |
| 6s to 8s | The agent steps down: it removes its WireGuard interfaces and releases the Lease. It joins the election again once Envoy is ready. 6s matches the probe, so a shorter stall moves nothing: a handover resets every connection across the site's gateway. |
| about 1s more | A standby whose Envoy is ready takes the Lease. The controller points the gateway Services, the remote endpoints and the `Import` Services at it. With one replica, the same replica takes the Lease again once its Envoy is ready, and creates its WireGuard interfaces again: each of its `wireguard` links handshakes again. Traffic is the same as with no step-down, since the controller publishes no gateway address while the pod is not ready. |

## Gateway rollout

The chart sets no rollout strategy, so the Deployment's defaults apply: up to 25% more pods than `replicas`, rounded up, and up to 25% fewer ready pods, rounded down. With 2 replicas: one new pod at a time, and no old pod stops before a new one is ready.

| Step | Event |
|---|---|
| 1 | The Deployment starts a new pod, which joins the election as a standby once its Envoy is ready. |
| 2 | It stops an old pod. Among the old pods that are ready, it stops those with the lowest deletion cost first: the standbys (requirement 39). An old pod that is not ready goes before any ready one. |
| 3 | Steps 1 and 2 repeat until the active pod is the only old pod left. Then it stops. Its agent removes its WireGuard interfaces and releases the Lease. A new pod takes it, as in the failover sequence above: one move of the Lease per rollout. |

A scale-down of `replicas` also stops the standbys first.

# Security Considerations

See [RFC#0007]. In short: peers reach the control and export ports only; import and peer listeners bind to the pod address, and an `Import`'s Service is `ClusterIP`; a `wireguard` link admits only the peer's key and tunnel address; a `direct` link is trusted by declaration. Endpoint-direct writes addresses from the peer's document into local EndpointSlices, so requirement 35 limits them, and `direct.endpointCIDRs` limits them to the peer's ranges.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| One gateway replica carries traffic at a time. | A site whose cross-site traffic exceeds one replica. |
| A WireGuard interface needs the kernel module on the node. | A cluster whose nodes lack it. A userspace driver would then be added. |
| One port per export. SNI routing is not served. | `PerMember` mode. |
| A controller that starts counts the gateway Lease as valid for its full `leaseDurationSeconds` from when it first reads it (requirement 32), as client-go's leader election does. A holder whose agent stopped renewing just before then stays the active gateway for up to 6s more, while its pod is ready. Reading `renewTime` instead would compare the holder's clock with the controller's, which requirement 32 forbids. | A way to tell, at first sight, a Lease that is still renewed from one that is not, without the holder's clock. |
| The default gateway ports that peers reach, the control port 30900, the export ports 30901-31899 and the WireGuard listen port 31820, are in the default node port range, from which Kubernetes gives a port to each Service that names none. Another Service can get a gateway port before the gateway Service names it. The API server then refuses the whole gateway Service, so it takes no new port, and the `GatewayServices` condition holds the API server's error. | A cluster where another Service takes a gateway port. |
| With a `NodePort` direct Service and `externalTrafficPolicy: Local`, only the node of the active gateway serves the Service. A `direct.address` names one node, so the link is unhealthy while the active gateway runs on another node, and traffic takes the next link. | A `direct` link with more than one address. |
| No metric counts the bytes of a `direct` link. Envoy counts bytes per cluster, and labels its stats per endpoint with the endpoint's address. `strait_gateway_link_connections` counts the open connections per link. | An operator who needs a link's bytes, for example to bill it. |
| The upgrade that brings requirement 43 changes the stat names of each `Export` and `Import` whose name holds a dot, so Envoy replaces their listeners and clusters once. Envoy closes the connections of a replaced listener at the end of its drain time, 10 minutes by default. The gateway rollout of the same upgrade resets them anyway. | None. |
