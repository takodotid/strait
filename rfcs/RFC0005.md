<h1 style="text-align: center;">[RFC#0005] Data Plane</h1>

# Abstract

The data plane carries the TCP traffic of application names between sites. Each site runs one gateway. Gateways are joined by links, each with a transport and a cost. This RFC fixes the link resources, the `direct` and `wireguard` transports, the gateway and its Envoy driver, health per export, link failover by cost, and endpoint-direct mode.

# Overview

```
site b                                                        site a
app -> pg.app.svc -> gateway b, import listener --link--> gateway a, export listener -> pg-a-rw -> primary
```

| Resource | Says |
|---|---|
| `Site` | This site's name, the gateway's ports, how peers reach them, the WireGuard private key's Secret. |
| `SitePeer` | A peer's name, its control port, its WireGuard public key. |
| `SiteLink` | One path to a peer: transport, cost, encryption, addresses. |
| `Export` | A local Service port that peers may reach, on a gateway port. |
| `Import` | A peer's export, offered locally on a gateway port. |

A `SiteService` creates its `Export`s and `Import`s ([RFC#0002]). They can also be written by hand to carry a plain TCP service between sites.

# Motivation

| Observed failure or reason | Choice |
|---|---|
| An inbound connection forwarded to the application name loops back over the link when the site is not active. | Inbound traffic always goes to the export's local Service. |
| Envoy spills traffic across priority levels when a level is partly healthy (default overprovisioning factor 1.4). A pair would use two links at once. | The overprovisioning factor is raised so one level takes all traffic while any of its endpoints is healthy. |
| Envoy's panic mode sends traffic to unhealthy endpoints when too few are healthy. | The panic threshold is 0. No healthy endpoint means the connection is closed at once. |
| A WireGuard key can be live in one place only. Two replicas that hold the same key reset each other's sessions. | One gateway replica is active at a time. The others are warm standbys. |
| Reloading a proxy to change endpoints drops or delays connections. | Envoy takes its configuration over xDS, with no reload. |
| A TCP check of a peer's export port succeeds while the peer's member is down, since the peer's Envoy accepts the connection. | Health per export is an HTTP check on the peer's control port, which answers from the export's endpoint health. |
| In the benchmark, on two proxy hops, Envoy cost about 50 µs more per round trip than HAProxy and about 7% more CPU, and moved 1.7 to 2.6 times as much data at defaults. Against a cross-site round trip of 1 ms or more, 50 µs is 5% or less ([docs/benchmark.md](../docs/benchmark.md)). | Envoy is the only driver. An HAProxy driver is a Limitation. |
| In the benchmark, when the gateway's node ran short of CPU, both proxies slowed down 35 to 40 times, far more than they differed. | The gateway's CPU request is set per site in the chart's values. |
| Kernel WireGuard runs in the gateway pod's own network namespace with `NET_ADMIN` only. A userspace tunnel (wireguard-go with a netstack) needs no capability, but carried about a quarter of the kernel's throughput on one TCP stream in kind, and puts the agent in the data path. | Kernel WireGuard, created by the gateway agent through netlink. A userspace driver is a Limitation. |

# Requirements

## Links

1. A `SiteLink` MUST name one `SitePeer`, one transport and a cost between 0 and 65535.
2. Among the healthy links to a peer, traffic MUST use the one with the lowest cost, then the lowest name. Other links MUST carry no new connection while it is healthy.
3. A link MUST count as healthy while the peer's control port answers `GET /healthz` over it. A link that fails two checks in a row, one second apart, MUST count as unhealthy. A check fails when no answer arrives within 500ms.
4. When the active link becomes unhealthy, new connections MUST use the next healthy link within 5 seconds.
5. `SiteLink.status` MUST show whether the link is healthy and whether it is the active link.

## Transports

6. A `direct` link MUST carry traffic to the peer gateway's address on the link with no tunnel, and MUST declare `encryption: None`.
7. A `wireguard` link MUST carry traffic in a WireGuard tunnel between the two gateways, keyed by the `Site`'s private key and the `SitePeer`'s public key.
8. A `wireguard` link with an `endpoint` MUST dial it and send keepalives. A link without one MUST wait for the peer to dial. Traffic MUST flow both ways once the peer has dialed.
9. Each `wireguard` link MUST have its own interface in the gateway pod's network namespace, and MUST NOT change any route or interface outside it.

## Gateway

10. The gateway MUST run as a Deployment with a configurable number of replicas. Exactly one replica, the holder of the `strait-gateway` Lease, MUST be active. Only the active replica MUST hold WireGuard interfaces.
11. The gateway Services and the remote endpoints of application names MUST point at the active replica only.
12. The proxy driver in v1 MUST be Envoy, configured over ADS by the elected controller. An endpoint change MUST NOT restart or reload Envoy.
13. Every export MUST have its own listener on its gateway port, and MUST forward only to its local Service's ready endpoints.
14. Every import MUST have its own listener on its gateway port, bound to the gateway pod's address, and MUST forward to the peer's export over the active link.
15. Each import's cluster MUST have one priority level per link to the peer, ordered by requirement 2, with an overprovisioning factor of at least 100000 and a panic threshold of 0.
16. The control port MUST answer `GET /healthz/exports/<namespace>/<name>` with 200 while the export has a healthy endpoint, and 503 otherwise.
17. An import's endpoint on a link MUST count as healthy only while the peer answers 200 for that export over that link.

18. A link's peer address MUST be an IP address: `direct.address` and `wireguard.peerAddress`. Envoy's EDS takes IP addresses only. `wireguard.endpoint` MAY be a host name; the gateway agent resolves it.

## Endpoint-direct

19. Endpoint-direct MUST apply only to a `direct` link with `endpointDirect: true`, and only while that link is the active, healthy link to the peer.
20. While it applies, the endpoints of an application name for a member at that peer MUST be the member's own addresses and port from the peer's document ([RFC#0004]).

# Design

## Gateway pod

| Container | Does |
|---|---|
| `envoy` | Carries traffic. Configuration from the controller over ADS. Node ID is the pod name. |
| `agent` | Takes part in the Lease. While active: creates the WireGuard interfaces, publishes the public key, reports link health from Envoy's admin interface. |

Standby replicas run Envoy with the same configuration, so a new active replica only needs its WireGuard interfaces. The controller reads the Lease to find the active pod.

## Ports

| Port | Bound to | Reached by | Serves |
|---|---|---|---|
| `Site.spec.gateway.controlPort` (30900) | all addresses | peers | `/healthz`, `/healthz/exports/...`, `/v1alpha1/observations` |
| `Site.spec.gateway.exportPorts` (30901-31899) | all addresses | peers | One export each. |
| `Site.spec.gateway.importPorts` (15000-15999) | pod address | local pods | One import each. |
| `Site.spec.gateway.peerPort` (14999) | pod address | the controller | `/peers/<peer>/...` to each peer's control port. |
| `SiteLink.spec.wireguard.listenPort` (51820) | all addresses, UDP | peers | WireGuard. |

The controller keeps two Services that point at the active replica:

| Service | Ports | Exposure |
|---|---|---|
| `strait-gateway-direct` | control, every export | `Site.spec.gateway.directService`, on the private link only |
| `strait-gateway-wireguard` | every WireGuard listen port | `Site.spec.gateway.wireGuardService` |

With `NodePort`, each node port equals its port, so the same port number reaches a gateway on every path.

## Envoy configuration

| Object | Name | Shape |
|---|---|---|
| Listener | `export/<ns>/<name>` | TCP proxy to cluster `export/<ns>/<name>`. |
| Cluster | `export/<ns>/<name>` | EDS: the ready endpoints of the export's Service, on its target port. |
| Listener | `import/<ns>/<name>` | TCP proxy to cluster `import/<ns>/<name>`. |
| Cluster | `import/<ns>/<name>` | EDS: one endpoint per link, at the link's peer address and the export's remote port. Priority by link rank. HTTP health check on the peer's control port, path `/healthz/exports/<ns>/<export>`. |
| Listener | `control` | HTTP. One health check filter per export, with `cluster_min_healthy_percentages` on `export/<ns>/<name>`. Routes `/healthz` to a direct 200, `GET /v1alpha1/observations` to the controller. Everything else 404. |
| Listener | `peers` | HTTP. Route prefix `/peers/<peer>/` to cluster `peer/<peer>`, prefix rewritten to `/`. |
| Cluster | `peer/<peer>` | EDS: one endpoint per link at the peer's control port. Priority by link rank. HTTP health check `/healthz`. |
| Cluster | `controller` | The controller's Service, observation port. |

| Setting | Value | Why |
|---|---|---|
| Health check interval, timeout | 1s, 500ms | Requirement 4. A dead path is marked unhealthy within about 2.5s. |
| Unhealthy threshold, healthy threshold | 2, 2 | One lost packet does not fail a link over. |
| `ClusterLoadAssignment.policy.overprovisioning_factor` | 100000 | Requirement 15. |
| `common_lb_config.healthy_panic_threshold` | 0 | Requirement 15. |
| Health check filter minimum healthy percentage | 1 | Envoy truncates it to an integer, and 0 lets an empty cluster pass. With up to 100 endpoints, any one healthy endpoint is enough. |
| TCP proxy `idle_timeout` | 0, disabled | Pooled database connections stay idle for hours. Envoy's default of 1 hour would cut them. |
| Upstream TCP keepalive | 30s, then every 5s, 3 probes | Finds a connection whose link died, since the idle timeout no longer does. |
| ADS port of the controller | 18000 | |

The link address is `direct.address` for a `direct` link and `wireguard.peerAddress` for a `wireguard` link.

## WireGuard

| Setting | Value |
|---|---|
| Interface name | `st` and the first 8 hex digits of the FNV-1a hash of the `SiteLink`'s name. |
| Private key | The Secret named by `Site.spec.wireguard.privateKeySecretRef`, in the gateway's namespace. |
| Peer public key | `SitePeer.spec.wireguard.publicKey`. |
| Allowed IPs | `wireguard.peerAddress`, as a /32 or /128. |
| Address | `wireguard.address`, on the interface. |
| Keepalive | `wireguard.persistentKeepalive`, only when `endpoint` is set. |

The host's kernel MUST provide the `wireguard` module. The gateway agent does not load it.

## Failover sequence

| Time | Event |
|---|---|
| 0s | The `direct` path to the peer fails. |
| up to 2s | Two health checks fail. Envoy marks the `direct` endpoints of every `peer/` and `import/` cluster unhealthy. |
| at once | New connections use the next priority, the `wireguard` link. Connections on the failed path end with it. |
| next agent poll, 1s | `SiteLink.status` shows the change. |

| Time | Event, when the active gateway replica fails |
|---|---|
| 0s | The active replica stops renewing the `strait-gateway` Lease. A replica that is shutting down releases it at once. |
| up to 6s | The Lease expires. A standby takes it and creates the WireGuard interfaces. |
| at once | The controller points the gateway Services and the remote endpoints at the new replica. |
| about 2s more | Envoy's health checks pass twice on the new replica's `wireguard` links, after a handshake. `direct` links pass as soon as the checks do. |

# Security Considerations

See [RFC#0007]. In short: peers reach the control and export ports only; import and peer listeners bind to the pod address; a `wireguard` link admits only the peer's key and tunnel address; a `direct` link is trusted by declaration.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| One gateway replica carries traffic at a time. | A site whose cross-site traffic exceeds one replica. |
| A WireGuard interface needs the kernel module on the node. | A cluster whose nodes lack it. A userspace driver would then be added. |
| One port per export. SNI routing is not served. | `PerMember` mode. |
| No HAProxy driver. The benchmark found no meaningful difference while the gateway has CPU to spare. | A site whose round trip between sites is well under 1 ms, so that 50 µs matters, or a benchmark on real links that shows a meaningful difference. |
