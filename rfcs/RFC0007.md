<h1 style="text-align: center;">[RFC#0007] Security</h1>

# Abstract

This RFC sets what each Strait component may do in a cluster, which credentials exist and where they live, how a link authenticates the site at the other end, and how a release proves where its artifacts come from.

# Overview

| Asset | Threat | Control |
|---|---|---|
| The workload | Strait changes it by mistake or by compromise. | Read-only RBAC on workload resources. Plugins get a reader. |
| The link | A third party injects or reads traffic between sites. | WireGuard keys, or a private link declared trusted. |
| The WireGuard private key | It leaks. | Held in one Secret, read by the gateway agent only, never printed. |
| Other clusters | A compromised site reaches into another site's API. | No site holds credentials to another site. Sites share only the observation document. |
| Application data | Strait reads it. | Strait carries TCP and never parses it. Application TLS stays on. |
| Local addresses | A peer's document points a local name at an address of its choice, through endpoint-direct. | Only IP addresses that are not special, and, with `direct.endpointCIDRs`, only the peer's ranges ([RFC#0005]). Without it, `strait validate` warns, and the link's condition `EndpointsLimited` is `False`. |
| Dependency updates | A change outside the repository changes which updates Renovate proposes, and how. | Renovate's built-in presets only. |
| The release | A tag on unreviewed or failing code publishes. A re-run replaces a published version. A forged image, chart or archive reaches a site. | A release only from a signed tag on `main` with green CI, tested before any push. No version replaced. The chart names the image by digest. Keyless signatures and attestations. |

# Motivation

| Reason | Choice |
|---|---|
| A credential that is never issued cannot leak. | No kubeconfig of another cluster. No database credential unless the operator opts in to `confirmRole`, and then one role that can only log in. |
| Envoy parses data from peers, so it has the largest attack surface in the gateway. | Envoy gets no Kubernetes token, no capability, and runs as non-root. |
| A tunnel interface needs `NET_ADMIN`. | Only the gateway agent container gets it, and only in the gateway pod's network namespace. |
| A private link may already be trusted and encrypted below Strait. Encrypting twice costs CPU for nothing. | `encryption: None` is allowed on `direct` links, only when declared. |
| A `NodePort` Service opens the export ports, in clear, on every node address, public ones included. | The direct Service is `ClusterIP` until the operator exposes it. |
| A `NodePort` or `LoadBalancer` Service admits any client that reaches a node or the load balancer. Only the peer gateways need the gateway Services. | The gateway Services take `loadBalancerSourceRanges`, `allocateLoadBalancerNodePorts` and `externalTrafficPolicy` ([RFC#0005]), so the operator can admit the peers only. |
| A review found that no policy covered the gateway pods, that the controller's policy admitted every source to its metrics, and that the gateway agent's probe server listened on every address of the pod's network namespace, including those of the WireGuard interfaces. | An optional policy on the gateway pods, a list of the sources of the metrics, and the probe server on the pod's own address. |
| A review found that the controller's rule on Leases named no Lease, so a compromised controller could write the gateway's `strait-gateway` Lease and pick the active gateway replica. | The controller may update its own Lease only. |
| A review inferred that a gateway rollout could move the gateway Lease twice, and reset every connection across the site's gateway each time ([RFC#0005]). A pod's deletion cost decides which pod a rollout deletes first. The gateway agent runs as root next to Envoy, which parses data from peers. The controller already sets Envoy's whole configuration. | The controller sets the deletion cost of the gateway pods, and may patch the pods of its namespace. The gateway agent may not. |
| A review found that the controller could write every Service and EndpointSlice of the cluster. The code refuses a Service that another owner holds, but a compromised controller could point any Service at an address of its choice. Kubernetes grants a namespaced resource per namespace. | The chart value `controller.namespaces` limits those writes to the namespaces of the site's `SiteService`s and `Import`s, and the release namespace. |
| A review found that the controller cached every Service and EndpointSlice of the cluster, and CloudNativePG's objects, under a 256Mi memory limit, also with `controller.namespaces`. In a large cluster it could run out of memory, and while it restarts, the other sites count this site's members `Unknown`. Limiting the reads with `controller.namespaces` would change that value's meaning, and leave an `Export` of another namespace with no endpoints. | The chart value `controller.namespacedReads`, off by default, limits those reads, and the controller's cache, to the namespaces of `controller.namespaces` and the release namespace. |
| With `externalTrafficPolicy: Cluster`, kube-proxy replaces the client's address with a node's address. A policy on the gateway pods cannot tell a peer from any other client. | `externalTrafficPolicy: Local` keeps the client's address. |
| A review found that a `v*` tag on any commit, merged or not, published the image, the chart and the GitHub release. The release pushed the image tags before its tests ran, and ran the tests in a job that held tokens to write packages and releases. | The release checks the tag, its commit and the commit's CI first. Tests run in a job that can write nothing. |
| A review found that the chart named the image by a tag, that a re-run of the release could push a version again, and that nothing was signed. A tag can move, so a site could run an image that no release built. | The chart names the image by the digest its release pushed. The release refuses a version that exists. Sigstore signs with the workflow's short-lived identity, so no signing key exists to leak. |
| A review found no check of the module's dependencies or of the chart in CI, and actions and tools that a workflow fetched by a tag or as the latest version. | CI verifies the module, scans for known vulnerabilities, and lints the code and the chart. Workflows pin each action and tool. |
| A review inferred that a peer of a `wireguard` link could reach the gateway pod's own address through its tunnel: WireGuard checks only the source of what it decrypts against the allowed IPs. A test in network namespaces used the gateway agent's own interface code. In it, a peer that allowed every address on its side, and routed the gateway pod's address into its tunnel, reached the import, peer, probe and metrics ports on that address, over IPv4 and IPv6. Linux delivers a packet to any of its addresses, whatever interface it arrives on, so a listener on the pod's address does not keep a tunnel out. | The gateway agent drops what arrives on a WireGuard interface for any address but the gateway's tunnel addresses. |
| A review found that this filter acted only on packets that the pod's network namespace delivers to itself. A packet from a link addressed to another address, such as another pod's, was forwarded: a new network namespace starts with the host's IPv4 forwarding setting. In the same test, with the gateway's namespace forwarding, the peer reached a listener at another namespace's address over IPv4 and IPv6. | The gateway agent also drops every packet from a WireGuard interface that its namespace would forward. |
| A review found that the gateway's policy, when on, admitted every pod of the cluster to every port of the gateway pod: the gateway agent's probes and metrics, and the peer port, through which a pod could read the peers' observation documents. Local pods need the import ports only, and the controller the peer port. | With `networkPolicy.gateway.enabled`, the pods of the cluster reach only the import and export ports, and the controller the peer port (operator, 2026-11-12). |
| A review found that the gateway's policy, when on, admitted `peerCIDRs` to every port of the gateway pod. A peer that reached the gateway pod's address, rather than a gateway Service, reached its probes, metrics, import ports and peer port. | The policy admits the peers to the control and export ports and the WireGuard listen ports only (operator, 2026-11-12). |
| A review found that `renovate.json` extended a preset of another repository, by branch, and that preset extended one of another organization, by branch. A change there would change which updates Renovate proposes for this repository, and how they are grouped and pinned, with no review here. | `renovate.json` holds its own settings, and extends Renovate's built-in presets only. |
| A review found that the image index was not reproducible, though the platform images were, and that no document said how to rebuild a release. The release attached BuildKit's provenance, `mode=max`, and an SBOM to the index. In two builds of one commit, the provenance differed in `startedOn`, `finishedOn`, `invocationId`, `buildConfig.digestMapping`, and the digests of the build stage's layers, and the SBOM in `creationInfo.created` and its random `documentNamespace`. | The index holds the platform images only, and the release attests each platform image with its provenance and SBOM with cosign, apart from the index (operator, 2026-11-12). A rebuild from the tag gives the published digests of the index and of the platform images, and [Rebuild a release](../docs/runbooks/rebuild.md) holds its steps. |
| A review found that Renovate updated neither the versions and SHA-256 that `.github/actions/` pins, nor the digest of the release's BuildKit image. Those pins went out of date unless someone changed them by hand. | Custom managers of `renovate.json` find them. |

# Requirements

## Permissions

1. The controller's RBAC MUST match the table in the Design section. Any rule beyond it is a change to this RFC. Checked by the unit test `TestRBAC`, which renders the chart and compares its rules with the tables.
2. The gateway agent's RBAC MUST match the table in the Design section. Its access to Secrets MUST be `get` on the one Secret named by `Site.spec.wireguard.privateKeySecretRef`. Checked by `TestRBAC`.
3. The Envoy container MUST NOT mount a Kubernetes service account token. The gateway pod MUST set `automountServiceAccountToken: false` and mount a projected token into the agent container only.
4. Every Strait container MUST drop all capabilities and run with a read-only root file system. Only the gateway agent MAY add `NET_ADMIN`. Every container except the gateway agent MUST run as non-root. The gateway agent runs as root, since Kubernetes grants an added capability to a non-root process in its bounding set only. The gateway's namespace therefore needs the Pod Security level `privileged`. Requirements 3 and 4 are checked by the unit test `TestContainers`, against the Containers table.
5. The CLI MUST be read-only ([RFC#0006]).

## Credentials

6. The repository MUST NOT hold a secret value. Manifests MUST reference Secrets by name.
7. The WireGuard private key MUST come from a Secret in the gateway's namespace. The public key MUST be published in `Site.status.wireGuardPublicKey`.
8. A component MUST NOT log or print a private key, a token or a Secret's data.
9. A component MUST NOT hold credentials to another cluster's API or to a workload. The one exception is the controller's role for `spec.plugin.cnpg.confirmRole`: a PostgreSQL role with `LOGIN` and nothing else, mounted only while the chart value `cnpg.confirmRole.secretName` is set ([RFC#0003] requirements 16 and 17).

## Links

10. A `wireguard` link MUST accept traffic only from the peer key in `SitePeer.spec.wireguard.publicKey`, and only from the peer's tunnel address.
11. A `direct` link MUST declare `encryption: None`. The CRD MUST reject a `direct` link without it. The direct Service MUST be `ClusterIP` when `Site.spec.gateway.directService.type` is unset, in the CRD default and in the controller.
12. Over any link, a peer MUST reach only the gateway's control port and export ports. The import listeners, the peer listener, and the gateway agent's probe and metrics servers MUST bind to the gateway pod's own address, so a tunnel address cannot reach them. The probe and metrics servers are checked by the unit tests `TestAgentProbeBindsThePodAddress` and `TestProbeListenAddr`. The gateway agent MUST drop each packet, IPv4 or IPv6, that arrives on a WireGuard interface and is addressed to anything but a tunnel address of the gateway, whether the pod's network namespace would deliver it or forward it, so a peer cannot reach the pod's own address, or any other address, through its tunnel. While it cannot put that filter in place, it MUST NOT create or change a WireGuard interface, and each `wireguard` link MUST show the error in its status. Checked by the unit tests `TestApply` and `TestApplyNeedsTheFilter`, and by `TestWireGuardPeerReachesOnlyControlAndExportPorts` in network namespaces (`make test-netns`).
13. The control port MUST serve only `GET /healthz`, `GET /healthz/exports/<namespace>/<name>` and `GET /v1alpha1/observations`.
14. The gateway MUST forward an export's traffic only to that export's local Service ([RFC#0005]).
15. Endpoint-direct MUST write only the member addresses that [RFC#0005] requirement 35 accepts.

## Writes by namespace

16. With `controller.namespaces` set, the chart MUST grant the controller the writes of Services and EndpointSlices only in those namespaces and the release namespace, and MUST pass them to the controller's flag `--namespaces`. The controller MUST NOT send such a write elsewhere: it MUST return an error that names the namespace, which the status of the `SiteService` or the `Import` shows ([RFC#0002] requirement 40, [RFC#0005]). Checked by the unit tests `TestRBAC`, `TestNamespacesFlagFollowsValue`, `TestNamespacedWrites`, `TestSiteServiceOutsideNamespaces` and `TestImportOutsideNamespaces`.

## Releases

17. The release workflow MUST publish only for an annotated tag `vX.Y.Z` whose signature GitHub verifies, whose commit is on `main`, and whose commit's `ci` run of its push to `main` has finished with every job of `ci.yaml` successful. Checked by the unit test `TestGate`, and by the release's job `gate`.
18. The release MUST NOT push an image, a chart or a GitHub release before `make verify test` and `make dist` pass on the tag's commit. Checked by the unit test `TestReleaseWorkflow`: each job that can write needs the job `test`, which runs them.
19. A job of the release that runs Go code of the module or of its dependencies on the runner MUST hold read permissions only. Checked by `TestReleaseWorkflow`, which refuses `go`, `make` and `actions/setup-go` in a job that can write.
20. The release MUST NOT replace a published version. It MUST stop when the image tag `X.Y.Z`, the chart version `X.Y.Z` or the GitHub release `vX.Y.Z` exists, or when the registry or GitHub does not answer that it is absent. It MUST check the three before its first push, and each again right before its own push. Checked by the unit test `TestAbsent`, and by `TestReleaseWorkflow`.
21. The released chart MUST name the Strait image by the digest that its release pushed, while `image.tag` and `image.digest` are both empty. Set alone, `image.tag` MUST name the image by that tag, as before. Checked by the unit test `TestImageDigest`, and by `hack/release/chart.sh`, which renders the packaged chart and fails unless every Strait image carries the digest.
22. The image tags `X.Y.Z` and `X.Y` MUST point at the image only once the image is signed and the chart is pushed and signed. Checked by `TestReleaseWorkflow`, and by the unit test `TestTags` of `hack/release/tags.sh`, which fails unless each tag names the digest.
23. The release MUST sign the image and the chart with Sigstore, keyless, under the workflow's OIDC identity, and MUST attest the CLI archives, the chart archive, `strait-crds.yaml` and `SHA256SUMS` with GitHub artifact attestations. It MUST attest each platform image of the image with BuildKit's SLSA v1 provenance, `mode=max`, and its SPDX SBOM, with cosign under the same identity, as the types `slsaprovenance1` and `spdxjson`, and MUST NOT put an attestation in the image's index. It MUST attest a platform image only with the attestations of a build that gave that image's digest. A long-lived signing key MUST NOT exist. Checked on each release by `cosign verify`, `cosign verify-attestation` and `gh attestation verify`, as [Install, Verify a release](../docs/guide/install.md#verify-a-release) shows, and before `publish` by the job `image-check`, which verifies the image's signature and both attestations of each platform image. `hack/release/attest.sh` attests nothing unless a second build of the commit gave each pushed platform image by its digest: checked by the unit test `TestAttest`, and the workflow by `TestReleaseWorkflow`.
24. A workflow MUST pin every action by commit SHA. The tools that `.github/actions/` installs MUST be pinned by version and SHA-256, and the release's BuildKit image by digest. Checked by `make lint`, through `hack/release/pinned.sh`, for the actions, and by review for the tools and BuildKit.
25. CI MUST run `go mod verify`, `govulncheck`, `staticcheck` and `helm lint` on each pull request and each push to `main`. Checked by the job `lint` of `ci.yaml`.

## Reads by namespace

26. With `controller.namespacedReads` set, the chart MUST grant the controller the reads of Services, EndpointSlices and CloudNativePG's `clusters` and `poolers` only in the namespaces of `controller.namespaces` and the release namespace, and MUST pass `--namespaced-reads` to the controller. The chart MUST refuse `controller.namespacedReads` without `controller.namespaces`. The controller's cache MUST then hold those kinds of those namespaces only. The controller MUST NOT send a read of them elsewhere: it MUST return an error that names the namespace, which the status of the `SiteService`, the `Export` or the `Import` shows. Checked by the unit tests `TestRBAC`, `TestNamespacedReadsFlagFollowsValue`, `TestNamespacedReads`, `TestCacheHoldsReadNamespacesOnly`, `TestSiteServiceOutsideNamespacedReads`, `TestImportOutsideNamespacedReads` and `TestExportOutsideNamespacedReads`.

## Dependency updates

27. `renovate.json` MUST extend only Renovate's built-in presets, at every level, and MUST NOT name a preset of another repository or of a package. Checked by the unit test `TestRenovatePresets`.

## Network policies

28. With `networkPolicy.gateway.enabled`, the gateway's policy MUST admit the pods of the cluster to the gateway's import and export ports only, the controller pods to its peer port only, and the CIDRs of `networkPolicy.gateway.peerCIDRs` to its control port and export ports over TCP, and the ports of `networkPolicy.gateway.wireGuardPorts` over UDP, only. With `site.create` true, the chart MUST take the gateway's ports from `site.spec.gateway`, and from the Site CRD's defaults where it sets none. With `site.create` false, it MUST take them from `networkPolicy.gateway.ports`, and MUST fail to render when that value lacks `controlPort`, `exportPorts`, `importPorts` or `peerPort`, or holds them with `site.create` true. With `peerCIDRs` set, it MUST fail to render while `wireGuardPorts` is unset; an empty list is a site with no `wireguard` link. Checked by the unit tests `TestNetworkPolicies`, `TestGatewayPolicyPorts` and `TestGatewayPolicyPeers`, and by the end-to-end `import` step, where kindnet enforces the policy: a pod reaches the import port, and not 8091.

## Updates of pinned tools

29. `renovate.json` MUST propose an update of each version that `.github/actions/` pins, and of the release's BuildKit image. The update MUST carry the new SHA-256 of cosign's `cosign-linux-amd64`, from its release's `cosign_checksums.txt`, and the new digest of the BuildKit image. Checked by the unit test `TestRenovateCustomManagers`, which runs each custom manager's pattern on the file it names. Helm's SHA-256 is set by hand ([Release, Known gaps](../docs/runbooks/release.md#known-gaps)).

## Rebuilds

30. The image's index, and each of its platform images, MUST rebuild from the release's tag to the digest that the release published, with the labels and annotations that the release wrote on them, the BuildKit image of its `release.yaml`, and no attestation. The index MUST list one OCI image manifest per platform, `linux/amd64` and `linux/arm64`, and nothing else, and name the release's version and commit in its annotations. Checked on each release by `hack/distcheck` in the job `image-check`, with the unit test `TestIndex`, and by `attest.sh`, which fails unless a second build from scratch gives each platform image by its pushed digest. Checked by the steps of [Rebuild a release](../docs/runbooks/rebuild.md), which gave the published digests of v1.4.0's platform images. Two builds of one commit, `ade11e2`, with the release's settings, gave the same index digest.

## Controller RBAC

Each row is one rule. Scope `Cluster` is a ClusterRole; `Its namespace` is a Role in the release namespace.

| API group | Resources | Verbs | Scope | Why |
|---|---|---|---|---|
| `strait.tako.id` | `siteservices`, `sites`, `sitepeers`, `sitelinks` | get, list, watch | Cluster | Inputs. |
| `strait.tako.id` | `exports`, `imports` | get, list, watch, create, update, patch, delete | Cluster | Owned by `SiteService`s. |
| `strait.tako.id` | `siteservices/status`, `sites/status`, `sitepeers/status`, `exports/status`, `imports/status` | get, update, patch | Cluster | Status. The gateway agent writes `sitelinks/status`. |
| core | `services` | get, list, watch | Cluster, or each namespace of `controller.namespaces` and its namespace with `controller.namespacedReads` | Application names, `Import` Services and gateway Services, and the Services of members and exports. |
| core | `services` | create, update, patch, delete | Cluster, or each namespace of `controller.namespaces` and its namespace | Application names, `Import` Services and gateway Services. `delete`: the Service of an `Import` without `spec.port`, and a gateway Service with no port. |
| `discovery.k8s.io` | `endpointslices` | get, list, watch | Cluster, or each namespace of `controller.namespaces` and its namespace with `controller.namespacedReads` | Routes, and the endpoints of members and exports. |
| `discovery.k8s.io` | `endpointslices` | create, update, patch, delete | Cluster, or each namespace of `controller.namespaces` and its namespace | Routes. |

| `events.k8s.io` | `events` | create, patch | Cluster | Route changes and alerts. |
| `postgresql.cnpg.io` | `clusters`, `poolers` | get, list, watch | Cluster while `cnpg.enabled`, or each namespace of `controller.namespaces` and its namespace with `controller.namespacedReads` | The `cnpg` plugin. |

## Sources of the gateway Services

| Service | Ports | Sources that must reach it |
|---|---|---|
| `strait-gateway-direct` | Control port and export ports, TCP | The peer gateways, over `direct` links. |
| `strait-gateway-wireguard` | WireGuard listen ports, UDP | The peer gateways, over the network of `wireguard` links. |

No other client needs them. Local pods reach an import on the gateway pod's address or on the `Import`'s Service ([RFC#0005]).

A peer gateway's connection arrives from the peer gateway pod's address, or from a peer node's address when the peer's cluster masquerades traffic that leaves it, that is, rewrites its source address.

| Service type | Admits the peers only with |
|---|---|
| `LoadBalancer` | `loadBalancerSourceRanges` set to the peers' source addresses. `allocateLoadBalancerNodePorts: false` also keeps the ports off the nodes, for a load balancer that sends traffic to the pods directly. |
| `NodePort` | `externalTrafficPolicy: Local`, and a network policy on the gateway pods that admits the peers' source addresses. Only the node of the active gateway then serves the Service ([RFC#0005], Limitations). |

## Network policies

| Policy | Pods | Admits | In the chart |
|---|---|---|---|
| `strait-controller` | The controller | The gateway pods, to the observation port 8082 and the xDS port 18000. Every source, to the probes, 8081. The sources of `networkPolicy.metricsFrom` to the metrics, 8080, or every source when it is empty. | On, `networkPolicy.enabled` |
| `strait-gateway` | The gateway | Every source, to the gateway agent's probes, 8090. The sources of `networkPolicy.metricsFrom` to the gateway agent's metrics, 8091, or every source when it is empty. Every pod of the cluster, to the import and export ports: clients of imports and exports. The controller, to the peer port: its polls of peers. The CIDRs of `networkPolicy.gateway.peerCIDRs`, the peers' source addresses as the table above gives them, to the control port and the export ports over TCP, and to the WireGuard listen ports of `networkPolicy.gateway.wireGuardPorts` over UDP. The chart does not read `SiteLink`s, so that value lists the listen ports. | Off, `networkPolicy.gateway.enabled` |

The gateway's policy names each range of ports with `endPort`. Envoy's admin interface, 9901, listens on 127.0.0.1 only, so no policy needs to name it.

Under any policy, Kubernetes admits traffic from a pod's own node, which runs its probes. Some CNIs can enforce policies on traffic from the host too, so each policy admits every source to the probe port, which serves `/healthz` and `/readyz` only. The gateway policy is off by default. The peers' source addresses depend on the gateway Services' type and on the CNI. No default fits every site, and a wrong one cuts the peers off.

## Releases

Each job of `release.yaml`, in order:

| Job | Needs | Permissions | Does |
|---|---|---|---|
| `gate` | | `contents: read`, `actions: read` | Requirement 17. Checks that no version exists (requirement 20). |
| `test` | `gate` | `contents: read` | `make verify test`. The CLI archives with `make dist`, checked with `hack/distcheck` ([RFC#0006]), and `strait-crds.yaml`, kept for `publish`. |
| `image` | `test` | `contents: read`, `packages: write`, `id-token: write` | Builds the image for `linux/amd64` and `linux/arm64`, pushes its index, with the platform images only, by digest with no tag, and signs the digest. Builds it again from scratch, with BuildKit's provenance and SBOM, into an OCI layout on the runner, and attests each pushed platform image with them (requirements 23 and 30). |
| `image-check` | `image` | `contents: read` | Checks each platform of the pushed image with `hack/distcheck` ([RFC#0006]), and runs its `strait version` on `linux/amd64`. Checks the index with `hack/distcheck`, and verifies the image's signature and both attestations of each platform image. |
| `publish` | `test`, `image`, `image-check` | `contents: write`, `packages: write`, `id-token: write`, `attestations: write` | Packages the chart with the image's digest, writes `SHA256SUMS`, and attests. Then pushes and signs the chart, creates the GitHub release, and points the image tags `X.Y.Z` and `X.Y` at the digest, in that order. |
| `pages` | `publish` | `contents: read`, `pages: write`, `id-token: write`, as a ceiling | Calls `pages.yaml` with `publish`, which builds the documentation site from the tag and deploys it to GitHub Pages. Its build job holds `contents: read` only, and its deploy job holds `pages: write` and `id-token: write` and runs GitHub's `deploy-pages` action only. |

`image`, `publish` and `pages` run no Go on the runner. The image's builds run Go in BuildKit's build containers, which get neither the runner's environment nor its credentials. `image` runs shell, `jq`, `cosign` and `docker buildx` only, and `publish` shell, `helm`, `cosign`, `gh` and `docker buildx imagetools` only. The build job of `pages` runs bun and the site's npm packages, pinned by `docs/bun.lock`, and can write nothing. The image is built from the commit's time, `SOURCE_DATE_EPOCH`, and without a build cache, so that two builds of one commit give the same index and platform images.

`gate` runs in the environment `release`, so a review there holds back every later job.

A re-run of failed jobs runs those jobs and the jobs after them. If an earlier attempt already pushed a step's artifact, the run stops at that step (requirement 20). So a version whose run failed after its chart's push is released as the next patch version ([Release](../docs/runbooks/release.md)).

The signatures and attestations name the workflow and the tag:

| Field | Value |
|---|---|

# Limitations

| Limitation | What to do | Revisit when |
|---|---|---|
| The metrics of the controller and of the gateway agent are plain HTTP. `networkPolicy.metricsFrom` limits who reaches them. They hold names of objects and their states, no address and no secret. | Set `networkPolicy.metricsFrom` to the scrapers only. | A cluster that requires metrics over TLS. The controller and the gateway agent would then need the right to create TokenReviews and SubjectAccessReviews. |
| A CNI that does not support `endPort` admits only the first port of each range of the gateway's policy, so the pods of the cluster reach only the first import port and the first export port. | Use a CNI that supports `endPort`, or leave `networkPolicy.gateway` off. | A site whose CNI does not support `endPort`. |
| The xDS stream between the controller and Envoy is not encrypted. It stays inside the Strait namespace, and a NetworkPolicy admits only gateway pods. | Run a CNI that enforces NetworkPolicy. | A cluster without NetworkPolicy enforcement. |
| Rotating the WireGuard key needs the peers' `SitePeer` updated at the same time. | Follow [WireGuard key rotation](../docs/runbooks/wireguard-key-rotation.md). | Sites that must rotate keys often. |
| Without `controller.namespacedReads`, the controller reads every Service and EndpointSlice of the cluster, also with `controller.namespaces`. With it, an `Export` of another namespace has no ready endpoint. In both cases, the controller reads and writes `Export`s, `Import`s, their status and events in every namespace. | Set `controller.namespaces` and `controller.namespacedReads` where the controller must read less ([Sizing](../docs/sizing.md)). | A site whose Strait objects must stay in the namespaces of its `SiteService`s. |
| RBAC cannot limit `patch` on pods to the gateway pods, or to one annotation. On envtest's API server, a patch changed a pod's image and labels. A compromised controller could use this to run code in a gateway pod, with the gateway agent's `NET_ADMIN` and WireGuard private key, or to change the labels that select the pods of its namespace. | Limit who can act as the controller's service account, and watch the gateway pods' changes. | A site that needs a narrower right. A ValidatingAdmissionPolicy could admit from the controller a change of the deletion cost only. |
| Without `direct.endpointCIDRs`, endpoint-direct accepts any address from the peer that is not special. A compromised peer, or anyone on the path of a `direct` link, can point a local name at another address that the site's pods reach. `strait validate` warns ([RFC#0006] requirement 18), and the link's condition `EndpointsLimited` is `False` ([RFC#0005] requirement 48). `v1` accepts such a link, so refusing it would break objects that `v1` stored. | Set `endpointCIDRs` on each `direct` link with `endpointDirect` ([Before production](../docs/runbooks/before-production.md)). | The next API version: it requires `endpointCIDRs` with `endpointDirect`. |
