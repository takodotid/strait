<h1 style="text-align: center;">[RFC#0007] Security</h1>

# Abstract

This RFC fixes what each Strait component may do in a cluster, which credentials exist and where they live, and how a link authenticates the site at the other end.

# Overview

| Asset | Threat | Control |
|---|---|---|
| The workload | Strait changes it by mistake or by compromise. | Read-only RBAC on workload resources. Plugins get a reader. |
| The link | A third party injects or reads traffic between sites. | WireGuard keys, or a private link declared trusted. |
| The WireGuard private key | It leaks. | Held in one Secret, read by the gateway agent only, never printed. |
| Other clusters | A compromised site reaches into another site's API. | No site holds credentials to another site. Sites share only the observation document. |
| Application data | Strait reads it. | Strait carries TCP and never parses it. Application TLS stays on. |
| Local addresses | A peer's document points a local name at an address of its choice, through endpoint-direct. | Only IP addresses that are not special, and, with `direct.endpointCIDRs`, only the peer's ranges ([RFC#0005]). |

# Motivation

| Reason | Choice |
|---|---|
| A credential that is never issued cannot leak. | No kubeconfig of another cluster, no database credential. |
| Envoy parses data from peers, so it has the largest attack surface in the gateway. | Envoy gets no Kubernetes token, no capability, and runs as non-root. |
| A tunnel interface needs `NET_ADMIN`. | Only the gateway agent container gets it, and only in the gateway pod's network namespace. |
| A private link may already be trusted and encrypted below Strait. Encrypting twice costs CPU for nothing. | `encryption: None` is allowed on `direct` links, only when declared. |
| A `NodePort` Service opens the export ports, in clear, on every node address, public ones included. | The direct Service is `ClusterIP` until the operator exposes it. |
| A `NodePort` or `LoadBalancer` Service admits any client that reaches a node or the load balancer. Only the peer gateways need the gateway Services. | The gateway Services take `loadBalancerSourceRanges`, `allocateLoadBalancerNodePorts` and `externalTrafficPolicy` ([RFC#0005]), so the operator can admit the peers only. |
| A review found that no policy covered the gateway pods, that the controller's policy admitted every source to its metrics, and that the gateway agent's probe server listened on every address of the pod's network namespace, the WireGuard interfaces' included. | An optional policy on the gateway pods, a list of the sources of the metrics, and the probe server on the pod's own address. |
| A review found that the controller's rule on Leases named no Lease, so a compromised controller could write the gateway's `strait-gateway` Lease and pick the active gateway replica. | The controller may update its own Lease only. |
| A review inferred that a gateway rollout could move the gateway Lease twice, and reset every connection across the site's gateway each time ([RFC#0005]). A pod's deletion cost decides which pod a rollout deletes first. The gateway agent runs as root next to Envoy, which parses data from peers. The controller already sets Envoy's whole configuration. | The controller sets the deletion cost of the gateway pods, and may patch the pods of its namespace. The gateway agent may not. |
| A review found that the controller could write every Service and EndpointSlice of the cluster. The code refuses a Service that another owner holds, but a compromised controller could point any Service at an address of its choice. Kubernetes grants a namespaced resource per namespace. | The chart value `controller.namespaces` limits those writes to the namespaces of the site's `SiteService`s and `Import`s, and the release namespace. |
| With `externalTrafficPolicy: Cluster`, kube-proxy replaces the client's address with a node's address. A policy on the gateway pods cannot tell a peer from any other client. | `externalTrafficPolicy: Local` keeps the client's address. |

# Requirements

## Permissions

1. The controller's RBAC MUST match the table in the Design section. Any rule beyond it is a change to this RFC. Checked by the unit test `TestRBAC`, which renders the chart and compares its rules with the tables.
2. The gateway agent's RBAC MUST match the table in the Design section. Its access to Secrets MUST be `get` on the one Secret named by `Site.spec.wireguard.privateKeySecretRef`. Checked by `TestRBAC`.
3. The Envoy container MUST NOT mount a Kubernetes service account token. The gateway pod MUST set `automountServiceAccountToken: false` and mount a projected token into the agent container only.
4. Every Strait container MUST drop all capabilities and run with a read-only root file system. Only the gateway agent MAY add `NET_ADMIN`. Every container except the gateway agent MUST run as non-root. The gateway agent runs as root, since Kubernetes grants an added capability to a non-root process in its bounding set only. The gateway's namespace therefore needs the Pod Security level `privileged`. Requirements 3 and 4 are checked by the unit test `TestContainers`, against the Containers table.
5. The CLI MUST be read-only ([RFC#0006]).

## Credentials

6. The repository MUST NOT hold a secret value. Manifests MUST reference Secrets by name.
7. The WireGuard private key MUST come from a Secret in the gateway's namespace. The public key MUST be published in `Site.status.wireGuardPublicKey`.
8. A component MUST NOT log or print a private key, a token or a Secret's data.
9. A component MUST NOT hold credentials to another cluster's API or to a workload.

## Links

10. A `wireguard` link MUST accept traffic only from the peer key in `SitePeer.spec.wireguard.publicKey`, and only from the peer's tunnel address.
11. A `direct` link MUST declare `encryption: None`. The CRD MUST reject a `direct` link without it. The direct Service MUST be `ClusterIP` when `Site.spec.gateway.directService.type` is unset, in the CRD default and in the controller.
12. Over any link, a peer MUST reach only the gateway's control port and export ports. The import listeners, the peer listener and the gateway agent's probe server MUST bind to the gateway pod's own address, so a tunnel address cannot reach them. The probe server is checked by the unit tests `TestAgentProbeBindsThePodAddress` and `TestProbeListenAddr`.
13. The control port MUST serve only `GET /healthz`, `GET /healthz/exports/<namespace>/<name>` and `GET /v1alpha1/observations`.
14. The gateway MUST forward an export's traffic only to that export's local Service ([RFC#0005]).
15. Endpoint-direct MUST write only the member addresses that [RFC#0005] requirement 35 accepts.

## Writes by namespace

16. With `controller.namespaces` set, the chart MUST grant the controller the writes of Services and EndpointSlices only in those namespaces and the release namespace, and MUST pass them to the controller's flag `--namespaces`. The controller MUST NOT send such a write elsewhere: it MUST return an error that names the namespace, which the status of the `SiteService` or the `Import` shows ([RFC#0002] requirement 40, [RFC#0005]). Checked by the unit tests `TestRBAC`, `TestNamespacesFlagFollowsValue`, `TestNamespacedWrites`, `TestSiteServiceOutsideNamespaces` and `TestImportOutsideNamespaces`.

# Design

## Controller RBAC

Each row is one rule. Scope `Cluster` is a ClusterRole; `Its namespace` is a Role in the release namespace.

| API group | Resources | Verbs | Scope | Why |
|---|---|---|---|---|
| `strait.tako.id` | `siteservices`, `sites`, `sitepeers`, `sitelinks` | get, list, watch | Cluster | Inputs. |
| `strait.tako.id` | `exports`, `imports` | get, list, watch, create, update, patch, delete | Cluster | Owned by `SiteService`s. |
| `strait.tako.id` | `siteservices/status`, `sites/status`, `sitepeers/status`, `exports/status`, `imports/status` | get, update, patch | Cluster | Status. The gateway agent writes `sitelinks/status`. |
| core | `services` | get, list, watch | Cluster | Application names, `Import` Services and gateway Services, and the Services of members and exports. |
| core | `services` | create, update, patch, delete | Cluster, or each namespace of `controller.namespaces` and its namespace | Application names, `Import` Services and gateway Services. `delete`: the Service of an `Import` without `spec.port`, and a gateway Service with no port. |
| `discovery.k8s.io` | `endpointslices` | get, list, watch | Cluster | Routes, and the endpoints of members and exports. |
| `discovery.k8s.io` | `endpointslices` | create, update, patch, delete | Cluster, or each namespace of `controller.namespaces` and its namespace | Routes. |
| core | `pods` | get, list, watch, patch | Its namespace | The active gateway's address. `patch`: the deletion cost of the gateway pods ([RFC#0005]). |
| `coordination.k8s.io` | `leases` | get, list, watch, create | Its namespace | The gateway lease; its own leader election. RBAC cannot limit `create` to a name. |
| `coordination.k8s.io` | `leases` | update | Its namespace, `strait-controller` only | Its own leader election. It never writes the gateway lease. |
| `events.k8s.io` | `events` | create, patch | Cluster | Route changes and alerts. |
| `postgresql.cnpg.io` | `clusters`, `poolers` | get, list, watch | Cluster, while `cnpg.enabled` | The `cnpg` plugin. |

## Gateway agent RBAC

| API group | Resources | Verbs | Scope | Why |
|---|---|---|---|---|
| `strait.tako.id` | `sites`, `sitepeers`, `sitelinks` | get, list, watch | Cluster | WireGuard settings. |
| `strait.tako.id` | `sites/status`, `sitelinks/status` | get, update, patch | Cluster | Public key, link health. |
| core | `secrets` | get | Its namespace, the WireGuard Secret only | The private key: the one Secret that `Site.spec.wireguard.privateKeySecretRef` names. |
| `coordination.k8s.io` | `leases` | create | Its namespace | The gateway lease. |
| `coordination.k8s.io` | `leases` | get, update | Its namespace, `strait-gateway` only | The gateway lease. |

## Sources of the gateway Services

| Service | Ports | Sources that must reach it |
|---|---|---|
| `strait-gateway-direct` | Control port and export ports, TCP | The peer gateways, over `direct` links. |
| `strait-gateway-wireguard` | WireGuard listen ports, UDP | The peer gateways, over the network of `wireguard` links. |

No other client needs them. Local pods reach an import on the gateway pod's address or on the `Import`'s Service ([RFC#0005]).

A peer gateway's connection arrives from the peer gateway pod's address, or from a peer node's address when the peer's cluster masquerades traffic that leaves it.

| Service type | Admits the peers only with |
|---|---|
| `LoadBalancer` | `loadBalancerSourceRanges` set to the peers' source addresses. `allocateLoadBalancerNodePorts: false` also keeps the ports off the nodes, for a load balancer that sends traffic to the pods directly. |
| `NodePort` | `externalTrafficPolicy: Local`, and a network policy on the gateway pods that admits the peers' source addresses. Only the node of the active gateway then serves the Service ([RFC#0005], Limitations). |

## Network policies

| Policy | Pods | Admits | In the chart |
|---|---|---|---|
| `strait-controller` | The controller | The gateway pods, to the observation port 8082 and the xDS port 18000. Every source, to the probes, 8081. The sources of `networkPolicy.metricsFrom` to the metrics, 8080, or every source when it is empty. | On, `networkPolicy.enabled` |
| `strait-gateway` | The gateway | Every source, to the gateway agent's probes, 8090. Every pod of the cluster: clients of imports, and the controller's polls of peers. The CIDRs of `networkPolicy.gateway.peerCIDRs`: the peers' source addresses, as the table above gives them. | Off, `networkPolicy.gateway.enabled` |

Kubernetes admits a pod's own node, which runs its probes, under any policy. Some CNIs can enforce policies on traffic from the host too, so each policy admits every source to the probe port, which serves `/healthz` and `/readyz` only. The gateway policy is off by default: the peers' source addresses depend on the gateway Services' type and on the CNI, so no default fits every site, and a wrong one cuts the peers off.

## Containers

| Container | User | Capabilities | Token |
|---|---|---|---|
| controller | non-root | none | yes |
| gateway agent | root in its own network namespace | `NET_ADMIN` | yes, projected |
| Envoy | non-root | none | no |
| pre-pull | non-root | none | no |

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| The controller's metrics are plain HTTP. `networkPolicy.metricsFrom` limits who reaches them. | A cluster that requires metrics over TLS. The controller would then need the right to create TokenReviews and SubjectAccessReviews. |
| The xDS stream between the controller and Envoy is not encrypted. It stays inside the Strait namespace, and a NetworkPolicy admits only gateway pods. | A cluster without NetworkPolicy enforcement. |
| The observation document is not signed ([RFC#0004]). | A transport without its own authentication. |
| Rotating the WireGuard key needs the peers' `SitePeer` updated at the same time. | Sites that must rotate keys often. |
| The controller reads every Service and EndpointSlice of the cluster, also with `controller.namespaces`. It writes `Export`s, `Import`s, their status and events in every namespace. | A site whose Services must not be read outside the namespaces of its `SiteService`s. The controller's cache would then hold Services and EndpointSlices of those namespaces only, and an `Export` of another namespace would have no endpoints. |
| RBAC cannot limit `patch` on pods to the gateway pods, or to one annotation. On envtest's API server, a patch changed a pod's image and labels. A compromised controller could so run code in a gateway pod, with the gateway agent's `NET_ADMIN` and WireGuard private key, or change the labels that select the pods of its namespace. | A site that needs a narrower right. A ValidatingAdmissionPolicy could admit from the controller a change of the deletion cost only. |
| Without `direct.endpointCIDRs`, endpoint-direct accepts any address from the peer that is not special. A compromised peer, or anyone on the path of a `direct` link, can point a local name at another address that the site's pods reach. | Requiring `endpointCIDRs` with `endpointDirect`, in a new API version. |
